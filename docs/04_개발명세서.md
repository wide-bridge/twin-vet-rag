# TwinVet Care 개발명세서

버전: 0.6 · 작성일: 2026-11-09 · 상태: Claude Code 검토용 (0.6, 2026-11-13: MVP1 개발 명세 7절)

## 1. 구현 원칙

- 우선 구현: 서비스 기획서 P01~P09(PoC 완료). MVP1은 M01(온톨로지 0.1)·M02(수의사 HITL 데이터 파이프라인)이며 7절을 따른다. M03(보호자 대상 수의사 답변)은 후속이다.
- 아래 API는 프레임워크와 무관한 계약 초안이다. 개발자가 구현 복잡도를 검토해 변경 시 관련 흐름·화면·모델도 함께 수정한다.
- 원천 데이터가 없으면 임의 데이터를 실제 데이터로 취급하지 않는다. 합성 테스트 데이터는 명확히 구분한다.
- 확정 스택은 8절을 따른다. 답변 생성 LLM·배포 대상·예산은 미확정이다. Airflow 등 기존 학습 도구를 임의로 추가하지 않는다.

## 2. PoC API 계약

공통 경로: /api/v1. ID는 추측하기 어려운 식별자. 익명 세션 토큰은 Secure·HttpOnly 쿠키로 전달하고 상태 변경 요청은 CSRF/Origin을 검증한다.

GET /runs/{id}: 처리 중 answer는 null. completed에서는 answer={message_id,text}, citations=[{id,title}]. failed에서는 error={code,message,retryable}. 사용자에게 표시하는 메시지는 한국어로 통일한다.

반려견 정보의 형식·범위는 데이터모델 설계서 6절을 따른다. 필수값 누락·범위 밖 값은 422. life_stage는 입력으로 받지 않고 서버가 계산한 나이로 산출한다. 생년월일과 추정 나이를 함께 보내거나 둘 다 없으면 422, 미래 날짜·30년 11개월 초과는 422 invalid_birth_date. 반려견만 지원하며 동물 선택 필드는 받지 않는다. 상담 생성 후 반려견 정보는 고정하며 수정 API는 두지 않는다(변경은 새 상담).

P08·P09 계약은 2026-11-12 초안이다. 프로필 키는 세션과 별도의 Secure·HttpOnly 쿠키이며 DB에는 해시만 저장한다. POST /consultations는 프로필이 있으면 그 값을 복사해 상담을 만들고(clinic_id 포함), 프로필이 없으면 입력 dog로 상담과 프로필을 함께 만든다. 프로필이 바뀌어도 기존 상담은 바뀌지 않는다. 케어 목록은 현재 프로필 또는 현재 세션의 상담 중 보관 기간 안의 것만 반환한다. 병원 정보는 AI 프롬프트에 넣지 않는다.

GET /citations/{id}의 excerpt는 노출 기능이 켜지고 문서별 이용 조건이 확인된 경우에만 반환한다. UI에서 숨기기만 하는 방식은 금지한다.

## 3. 요청·상태 처리

- 질문은 공백 제거 후 비어 있으면 400. 길이 상한·요청 제한·처리 타임아웃은 설정값으로 두고 화면과 공유한다.
- 같은 상담·client_request_id·본문의 재요청은 기존 run을 반환한다. 같은 ID에 다른 본문이면 409.
- 처리 중 같은 상담의 새 질문은 409. 판정 순서: client_request_id 재요청 확인을 처리 중 409 검사보다 먼저 한다(재전송이 409를 받지 않게). 사용자 질문은 한 번만 저장한다.
- failed 요청의 명시적 재시도는 같은 client_request_id로 기존 run을 다시 queued로 전환한다. 성공 결과는 재생성하지 않는다.
- 클라이언트는 run 상태를 조회한다. 새로고침 시 messages 응답의 runs로 진행 상태를 복구한다.
- 작업 상태는 DB에 저장한다. 서버 재시작 후 멈춘 실행은 타임아웃 정책에 따라 failed 처리하여 영구 로딩을 막는다.
- 세션 없음/만료는 401, 다른 세션의 자원은 404, 요청 과다는 429. 내부 오류·API 키·원문 스택은 응답하지 않는다.
- 삭제와 실행이 겹치면 삭제된 상담에 결과를 다시 저장하지 않는다.

## 4. RAG 처리 — P02·P03·P07

1. 세션 소유권·입력 검증 후 질문과 실행 기록 저장.
2. 반려견 정보(품종·나이·건강상태)와 최근 대화 맥락을 반영해 검색 질의 구성. 품종·기존 질환은 질의 보강에 쓰고, 생애주기는 필터로 쓴다.
3. PostgreSQL pgvector에서 활성 Training 지식을 검색. 산출 생애주기 OR 공통 OR 미지정 문서를 포함. qa_case/reference를 모두 지원하고 top_k·임계값·맥락 길이는 설정으로 관리.
4. 응답 유형 판정 — 검색 점수만으로 유형을 정하지 않는다. 다음 순서로 판정한다.
   - (1) **범위 판정**(검색 전, 경량 LLM 분류 1회): 반려견 외 동물·비의료 주제 → out_of_scope. 판정 근거는 질문과 대화 맥락이며 검색 점수와 무관하다.
   - (2) **추가 확인 판정**(같은 분류 호출의 사실값으로 서버가 판정): 증상·대상이 전혀 특정되지 않음(60자 이하·이전 대화 없음일 때만 인정) 또는 입력 반려견 정보와 질문이 충돌 → clarification. 근거 검색 결과가 없어도 확인 질문은 할 수 있다.
     - 나이 충돌: 분류기가 질문 속 나이 표현을 그대로 옮기고 서버가 질문에 실제로 있는지 확인·환산한다. 생애주기가 다르고 2년 넘게 차이 나면 충돌. 입력이 생년월(일)이면 확인 질문, 출생 연도만·추정 나이면 질문 속 나이의 생애주기로 검색한다.
     - '더 알면 좋은 정보(체중·기간 등)'는 확인 사유가 아니다. 응급 가능 상황에서는 확인 질문을 하지 않는다.
   - (3) 범위 안이고 확인이 필요 없을 때만 검색한다. 최고 유사도가 임계값 미만이면 → insufficient_evidence(답변 생성 LLM 호출 생략).
   - (4) 임계값 이상이면 답변 LLM이 JSON 스키마로 response_type(grounded/insufficient_evidence)·답변·사용 근거 번호를 반환한다. 근거 번호는 서버가 이번 검색 결과의 1..k 번호와 대조하고, 유효 근거가 없는 grounded는 insufficient_evidence로 바꾼다.
   - 분류 호출 실패는 run failed(재시도 가능)로 처리하고 임의 유형으로 대체하지 않는다. 판정 경로(어느 단계에서 결정됐는지)를 answer_run에 기록해 평가에 쓴다.
4-1. 반려견 정보는 프롬프트에서 '보호자 입력 정보' 블록으로 분리한다. 답변은 입력 정보를 고려하되 근거에 없는 품종·나이 일반화를 하지 않는다. 입력 정보가 판단에 쓰였는지 답변에서 드러나게 한다(이름이 있으면 "두부(10세 말티즈)는…", 없으면 "입력하신 10세 말티즈 기준으로…"). 이름은 부르는 데만 쓴다.
5. 근거가 충분한 경우 제공된 내용에 기반한 답변 생성. 지식문서 안의 지시문은 실행 지시로 취급하지 않음.
6. 출처 ID와 검색 결과를 대조하고 답변·인용·실행 메타를 저장.
7. grounded 응답에 유효한 근거가 없으면 정상 근거 답변으로 전달하지 않고 부족 상태로 처리.

PoC에 임상 위험등급 판정 모델을 임의로 추가하지 않는다. 정보 제공 범위와 전문가 상담 안내를 명확히 한다. 모델 응답의 안전성과 근거 일치는 별도 평가한다.

## 5. 데이터 적재 — P06

운영자 전용 명령/스크립트로 원천 검증 → 정제 → 문서 버전 → 청크·임베딩 → 표본 검증 → 활성화를 수행한다. 해시로 중복 적재를 방지한다. 새 버전 실패 시 기존 버전을 유지한다. 비활성화·삭제 후 검색에서 제외되는지 확인한다. 공개 적재 API·관리자 UI는 PoC 기본 범위에 없다.

- qa_case는 질문·답변을 묶어 1건=1청크로 처리하고 한도 초과 사례는 별도 보고한다. reference는 절·문단 기준으로 나눈다.
- 원천의 문자 `\n`은 해당 본문 필드에서만 정상 줄바꿈으로 변환한다. 실측 6건(이전 "212건" 보고는 집계 오류, 데이터모델 설계서 5절 정정 참고).
- 로컬 전처리 명령: `python -m scripts.prepare_data --version v1` → `DATA_OUTPUT_DIR/prepared/v1/`에 qa_cases·reference_docs·reference_chunks·eval_dev·eval_final·excluded·report 저장. 네트워크·유료 API를 쓰지 않는다.
- (PoC) Validation 2,400건은 질문·정답 모두 색인 제외. 개발 평가군과 최종 검증군을 분리하고 Training 및 원천 자료와 중복 검사한다. MVP1부터는 서비스 기획서 7절 혼합안에 따라 지식 구축·라벨링에 활용하며, 기존 데이터 평가는 개발·회귀 평가로만 취급한다.
- 153번은 사용하지 않는다(PoC·MVP 모두 제외).
- 임베딩은 OpenAI `text-embedding-3-small`. 전처리 실측 27,577청크·약 1,679만 토큰(cl100k_base) × $0.02/1M = **약 $0.34(1회 전체 색인)**. 단가는 2026-11-09 OpenAI 가격표 기준이며 실행 전 재확인한다. 예산 확인 후 전체 임베딩을 실행하고 실제 사용량·비용을 보고한다.

| 용도 | 제안 모델 | 단가 | 근거 |
|---|---|---|---|
| 범위·확인 분류(4-(1)(2)) | `gpt-5-nano` | $0.05 / $0.40 | 짧은 분류. 가장 저렴 |
| 답변 생성(4-(4)) | `gpt-5-mini` (기본) | $0.25 / $2.00 | 한국어 근거 기반 요약에 충분한 품질·저비용. 품질 부족 시 `gpt-5.4-mini`($0.75 / $4.50)로 교체 비교 |

- 질문 1건 추정(가정: 분류 입력 1.5k·출력 0.2k, 답변 입력 5k(근거 6청크+반려견 정보+대화)·출력 1.2k(추론 토큰 포함)): 분류 약 $0.0002 + 답변 약 $0.0037 = **약 $0.004(약 5~6원)**.
- dev 평가 600건 1회: 답변 약 $2.4 + 채점 약 $1.5 = **약 $4**. final 1,799건 1회: **약 $12**. 최종 검증군은 확정 직전 1~2회만 실행한다.
- PoC 운영 월 1,000질문 가정 시 약 $4. 모델명은 설정(LLM_MODEL, LLM_CLASSIFIER_MODEL)으로 바꾸며 실제 비용은 answer_run.token_usage로 집계해 보고한다.
- 위 수치는 가정에 따른 추정이다. 측정 전 수치를 성과·확정 비용으로 기재하지 않는다.

### 권한

| 역할 | 할 수 있는 일 |
|---|---|
| vet | 검토 묶음 열람, 자기 라벨 작성·제출, 개념 제안, 지식 후보 작성, (자기가 라벨링하지 않은 묶음의) 발행 승인 |

프론트엔드는 상담 요약을 '이름(품종) | 나이 | 체중'(예: '두부(푸들) | 11세 5개월 | 5kg')으로 표시한다. 나이는 age_months를 년·개월로 표시하고 생년월일은 표시하지 않는다(정확도는 '약'·'(추정)'). 상담 요약에 생애주기 명칭·나이 구간을 렌더링하지 않는다. 서버의 생애주기 계산·검색 필터와 기존 DB/API 코드는 유지한다.

## 9. Neon 배포 결정 (2026-11-10)

- 사용자 결정: 배포 DB는 Neon 무료 PostgreSQL 전용 프로젝트 twin-vet-care. 기존 테이블명·스키마를 유지한다. 앱 호스팅은 무료 서비스로 준비하며 최종 서비스는 미확정이다.
- 이 결정은 위의 배포 DB 미확정 상태를 대체한다. 실제 연결·이전 완료를 뜻하지 않는다.
- DATABASE_URL은 앱 연결, ALEMBIC_DATABASE_URL은 같은 DB의 direct 마이그레이션 연결. SSL 필수. 접속 비밀값은 저장소에 기록하지 않는다.
- 로컬 개발은 기존 docker-compose.yml, Neon 연결은 단독 docker-compose.neon.yml 사용. 상세 이전·복구·검증 순서는 README를 따른다.
- 원천 자료 이용 조건 검토는 사용자 요청에 따라 후속으로 둔다. 발췌 차단은 유지한다.
- 무료 용량·compute, 지속적인 워커 DB 조회, 정리 작업 예약 및 백업/복구를 배포 전 기술 검증 항목으로 둔다.
- 앱 호스팅(2026-11-11 사용자 결정): Vercel. 서버리스라 상시 워커가 없으므로 RUN_MODE=request에서 브라우저가 POST /api/v1/runs/{id}/execute로 답변 처리를 요청한다(중복 호출 안전, 새로고침 후 재요청). DB는 Neon pooled 연결, 함수 지역 sin1.
- 점검 결과(2026-11-11): 덤프·복원 기준 DB 512 MB로 무료 1 GB 안에 들어간다(halfvec 전환 시 293 MB, 미적용). 워커는 대기 중 DB를 조회하지 않고 질문 접수 시 깨운다. 플랫폼 헬스 체크는 DB를 쓰지 않는 GET /api/v1/live를 사용한다.
