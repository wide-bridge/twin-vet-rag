# TwinVet Care 파트너 병원 프로그램 기획서

버전: 0.4 · 작성일: 2026-11-14 (0.2: 2026-11-15 공개 검증 요청 검토 / 0.3: 공개 검증 요청을 P1로 앞당김 / 0.4: 사업 3단계(시험 → 공개 수의사로 시작 → 제품·지속 데이터 파이프라인), 사용자 결정) · 상태: 기획 초안 (사용자 구상 정리, Codex 검토 전 — 2026-11-17 화요일 검토 예정)

관련 문서: 서비스기획서 4-1절(M03 보호자·수의사 연결), 4절(MVP1 HITL), 데이터모델 4-1·4-2절, 개발명세 7-1절, 화면설계 6절.

---

## 1. 한 문장 요약

> 동물병원은 **작은 수고(AI 답변 검토)**를 내고 **지역 보호자에게 실력 있는 병원으로 알려지며**, TwinVet은 그 수고로 **좋은 데이터**를 얻고, 병원의 평판·고객 관계가 TwinVet 안에 쌓이면 **락인**되어 나중에 **서비스 수수료**를 받는다.

## 2. 배경과 목적 (사용자 구상, 2026-11-14)

1. 동물병원은 **보호자(고객)에게 자기 병원을 알리기 위해** 참여한다. 병원 이름·로고를 TwinVet Care 로고 옆에 넣는다.
2. 나중에 병원에서 **서비스 수수료**를 받는다. 초반에는 **무료**로 하는 대신 **일정한 수고**를 받는다. 그 수고는 **처음에 작아야** 한다.
3. 수고를 하면 지역사회에 **유능한 수의사로 홍보**되어야 한다. 활동을 많이(그리고 잘) 한 수의사·병원이 **검색했을 때 잘 나와야** 하며, 이를 위한 지표가 필요하다(지식인 점수 같은 것).
4. 결론: **초반에는 좋은 데이터 확보, 나중에는 락인.**

## 2-1. 사업 단계 (2026-11-15 사용자 결정)

| 단계 | 목표 | 핵심 개념 | 끝났다고 보는 기준 |
|---|---|---|---|
| **1단계 — 시험 (가설 검증)** | **"공개 수의사 답글"이 "주치수의사 확보"보다 수월하고 확산 가능성이 크다**는 가설을 검증하고, 어느 길로 갈지 판단 | 공개 검증 요청 + 주치수의사(이미 구현) 둘 다 시험 모드로 운영 | 아래 1단계 검증 지표로 판단 근거 확보 |
| **2단계 — 공개 수의사로 서비스 시작** | 공개 수의사 답글로 서비스를 열고, **공개 수의사들이 점차 주치수의사가 되어 가면서** 서비스 확산 | 공개 요청(획득) → 주치수의사(관계) 전환 | 공개 요청 → 주치수의사 전환이 꾸준히 일어남 |
| **3단계 — 제품 판매와 지속 데이터 파이프라인** | **PawCheck 소변검사 스티커**, **Poochnio(스마트 포티)** 판매로 반려견 건강 데이터가 지속적으로 들어오는 파이프라인 완성 | **주치수의사가 기본**: 정기 검사 결과를 같은 수의사가 이어서 보고 해석·관리 | 기기·스티커 데이터 → AI 해석 → 주치수의사 확인 → 보호자 안내가 반복 운영 |

- 1단계는 **어느 쪽이 맞는지 정하는 단계**다. 공개 쪽이 수월하다는 것은 현재 가설이며 검증이 필요하다.
- 2단계에서 주치수의사는 처음부터 요구하는 조건이 아니라 **공개 요청의 결과로 생기는 관계**다.
- 3단계는 일회성 질문이 아니라 **같은 아이를 지속적으로 보는** 구조라서 주치수의사 개념이 필수다. 지금 만든 주치수의사(수락·유효기간·질문 보관) 구조가 그 기반이 된다.

### 1단계 검증 지표 (가설: 공개 수의사 답글이 더 수월하고 확산 가능성이 크다)
| 질문 | 측정 |
|---|---|
| 수의사가 참여하는가 | 초대한 수의사·병원 중 실제로 답한 비율, 첫 답변까지 걸린 날 |
| 꾸준히 하는가 | 주별 답변 수, 4주 유지 비율, 기본 의무(월 10건) 달성률 |
| 보호자에게 충분한가 | 공개 요청의 응답률·응답 시간(24시간 안 응답 비율), '도움 됐어요' 비율 |
| 관계로 이어지는가 | 공개 요청 답변 후 그 수의사에게 주치수의사 연결 요청한 비율, 수락률 |
| 데이터가 좋은가 | 검토 완료율, 보완 안내 비율, 안전 문제 지적, (P2) 2차 평가 일치율 |
| 비교 | 같은 기간 주치수의사 흐름의 연결 수·질문 수·응답률과 비교 |

- 1단계는 관리자 상담 스위치(시험 모드)로 시작하되, **가설 검증에는 실제 수의사 몇 명(예: 3~5명)의 시범 참여가 필요**하다. 시험수의사만으로는 화면·흐름까지만 확인된다.
- 시범 참여 수의사에게는 창립 파트너 혜택을 약속한다(4-7).

## 3. 이해관계자와 가치

| 주체 | 내는 것 | 얻는 것 |
|---|---|---|
| 동물병원·수의사 | 작은 수고(원클릭 검토, 선택적으로 회신·보완) | 지역 노출, 신뢰 표시(등급·배지·감사), 고객 연결(주치수의사·내원), 나중에 성과 리포트 |
| 보호자 | 질문, 선택적으로 품질 개선 동의 | 수의사가 확인한 안내, 가까운 믿을 만한 병원, 반려견 이력 |
| TwinVet | 플랫폼, AI, 노출 공간 | 현장 수의사의 검토 데이터(HITL), 병원이 데려오는 사용자, 락인 후 수수료 |

## 4. 구성 요소

### 4-1. 공동 브랜드
- 보호자 앱 상단 TwinVet Care 로고 옆에 **병원 이름·로고**("TwinVet Care × ○○동물병원").
- **그 병원과 관계 있는 보호자에게만** 표시한다. 모든 보호자에게 띄우면 광고처럼 보이고 다른 병원과 공정성 문제가 생긴다.
  - 그 병원 수의사가 **주치수의사**인 보호자 (1단계)
  - 그 병원 **QR·링크로 유입**된 보호자 (2단계)
  - 그 병원을 **주치동물병원**으로 등록한 보호자 (2단계, 병원이 파트너일 때)
- 병원 신원은 DB에 있는 **공공데이터 동물병원 목록**(약 1만 곳)과 연결해 확인한다. 기존 `clinic.is_partner` 칸을 활용한다.

### 4-2. 병원 QR 유입 (2단계)
- 병원 카운터 QR → 보호자는 처음부터 그 병원 브랜드로 시작하고, 그 병원 수의사에게 연결 요청까지 한 번에.
- 병원이 자기 고객에게 "우리 병원 AI 상담"을 주는 셈이고, TwinVet에는 **병원이 사용자를 데려오는 경로**가 된다.

### 4-3. 작은 수고 — 원클릭 검토
- **기본 의무 (제안)**: 한 달 AI 답변 **10건 원클릭 검토**. 건당 약 30초, 한 달 약 5분.
  - 결론: **맞아요 / 보완 필요 / 다르게 봐야 해요**
  - **안전 문제** 체크
  - 한 줄 의견 (선택)
- **선택 활동 (추가 인정)**: 보호자 질문 회신, AI 답변 보완(고쳐 쓰기), 문제 유형 표시.
- 문제 유형은 **AI 자동 점검기와 같은 이름**으로 맞춘다(사실 오류·빠진 경고·지나친 안심·반려견에 맞지 않음·근거와 다름). 그래야 "AI 점검기가 수의사와 얼마나 같은 판단을 하는지"를 측정할 수 있다.

### 4-4. 검토 큐 (2단계)
- 검토할 거리를 TwinVet이 공급한다. 보호자 질문이 적은 초반에도 데이터를 확보하기 위해서다.
  1. 그 병원 보호자가 보낸 질문의 AI 답변
  2. 품질 개선에 동의한 다른 질문의 운영자 정리본
  3. AI 자동 점검기가 '자신 없음'으로 표시한 답변
- 같은 사례를 다른 병원 수의사에게도 보내 **2차 검증**(앞 평가를 보지 않은 채)으로 품질 지표를 만든다.

### 4-5. 지수 (가칭 'TwinVet 케어 지수')
- **양만 세지 않는다.** 30초 검토를 아무렇게나 눌러도 오르는 지표는 데이터를 망친다. 품질을 넣어야 TwinVet의 "좋은 데이터"와 병원의 "노출"이 같은 방향이 된다.

| 요소 | 의미 | 이유 |
|---|---|---|
| 활동 | 최근 검토·회신 수, 시간이 지나면 감소 | 꾸준해야 유지(먼저 참여한 병원 독주 방지) |
| 품질 | 2차 검증·HITL 판단과의 일치율 | 대충 누르면 떨어짐 |
| 기여 | AI 답변 개선에 실제 반영된 건수 | TwinVet에 가장 가치 있는 행동 |
| 보호자 반응 | '설명이 도움 됐어요' | 보호자 소통 |
| 응답 | 회신까지 걸린 시간 | 보호자 경험 |

- 계산식은 데이터가 쌓인 뒤 정한다. 1단계에서는 **재료(활동 기록)만 쌓는다.**

### 4-6. 노출
- 병원 찾기·수의사 선택 목록: **거리 + 지수**로 정렬.
- 보호자에게는 숫자 순위 대신 **등급과 사실**만: "TwinVet 골드 파트너", "이번 달 AI 답변 검토 32건".
- 비교는 **지역 단위**(예: 강남구 파트너 병원 중 활동 상위). 작은 동네 병원도 자기 지역에서 돋보일 수 있게.
- **'제일 유능한' 같은 최상급 표현은 쓰지 않는다**(의료 광고 규제).

### 4-7. 동기 부여 (게이미피케이션, Codex 의견 반영)
- 보상은 **세 종류로 나누고 하나의 점수로 섞지 않는다.** 보호자가 좋아하는 답과 의학적으로 적절한 답은 항상 같지 않다.

| 보상 | 인정하는 행동 | 표시 예 |
|---|---|---|
| 활동 | 검토 완료(정정·재전송 중복 적립 없음, 시험 계정 제외) | "이번 달 검토 12건" |
| 보호자 도움 | 보호자의 '설명이 도움 됐어요·감사해요' | "받은 감사 8건", 도움 배지 |
| 지식 기여 | HITL 검증을 거쳐 실제 개선에 반영 | "AI 답변 개선 반영 1건", 기여 배지 |

- **'내 기여' 화면**: 검토 수, 받은 감사, HITL 채택, 실제 반영. 반영되면 **"선생님의 지적으로 이 답변을 개선했어요"** 결과 알림.
- **'이달의 TwinVet 기여 병원·수의사'**: 보호자 소통 / AI 품질 개선 / 꾸준한 참여 분야별. 처음에는 자동 순위가 아니라 **운영자가 근거를 확인해 선정**.
- **보호자 동의 여부로 불리해지지 않게**: 상담·검토 활동 인정과 HITL 활용 인정은 분리. 점수 때문에 보호자에게 동의를 재촉하는 구조를 만들지 않는다.
- 초기 참여 혜택: **'창립 파트너' 배지**와 무료 기간 보장(예: 1년).

### 4-8. 락인
- 병원 쪽: 지수·등급·배지·감사 기록(옮길 수 없는 평판), 주치수의사로 연결된 보호자, QR 유입 고객, 내원용 상담 요약.
- 보호자 쪽: 반려견 상담 이력, 주치수의사.

### 4-9. 유료 전환 (나중)
- 기본 참여(검토·노출 자격)는 **무료로 유지**해 데이터 공급을 끊지 않는다.
- 유료: 공동 브랜드 유지, 지역 상위 노출 **강화**, 월간 성과 리포트(노출·전화·지도 클릭·주치 등록 수), QR 고객 관리.
- **노출 자격은 품질로만 결정**하고 비용으로 사지 못하게 한다. 유료는 '강화'만, 품질 기준 미달이면 유료여도 노출하지 않는다.

### 4-10. 공개 검증 요청 — 주치수의사 없이 올리는 질문 (2026-11-15 검토, 미결정)

보호자가 주치수의사를 정하지 않고 "이 AI 답변을 수의사가 확인해 주세요"를 요청하면, 파트너 수의사들이 답하는 방식이다(지식인형). 주치수의사 흐름(1:1, 수락 필요)과 나란히 두는 **두 번째 입구**다.

**흐름 (안)**
```text
보호자: AI 답변 아래 [수의사 확인 요청] → 공유 내용 확인(질문·AI 답변·고른 반려견 정보, 기본 비식별)
  → 지역(시·구)과 진료 분야로 파트너 수의사들의 '공개 요청함'에 노출
수의사: 요청을 맡기(선점) → 검토 결론 + 보완 안내 → 보호자에게 전달
보호자: 답변 확인 → '설명이 도움 됐어요' → 마음에 들면 그 수의사에게 주치수의사 연결 요청(한 번에)
```

**장점**
| 대상 | 장점 |
|---|---|
| 보호자 | 수의사를 고를 필요 없이 바로 요청. 첫 사용 장벽이 낮다. 주치수의사가 없는 대부분의 초기 보호자도 쓸 수 있다 |
| 병원 | **새 고객을 만나는 통로.** 주치수의사 흐름은 이미 아는 고객 위주라 홍보 효과가 제한적인데, 공개 요청은 모르는 지역 보호자에게 실력을 보여 줄 기회 → 주치수의사 연결·내원으로 이어짐 |
| TwinVet | 질문이 한 병원에 묶이지 않아 **검토 데이터가 많이·고르게** 쌓인다. 같은 요청에 여러 수의사가 평가하게 하면 2차 검증·일치율 데이터가 자연스럽게 생긴다. 지수의 품질 요소를 만들기 쉽다 |
| 사업 | 주치수의사 → 락인, 공개 요청 → 획득. 두 입구가 깔때기를 이룬다(공개 요청으로 만나고 주치수의사로 묶는다) |

**단점·위험**
| 대상 | 단점·위험 | 대응 |
|---|---|---|
| 보호자 | 아무도 답하지 않을 수 있음(초기 수의사 수 적음). 대기 시간 불확실 | 응답 기한(예: 24시간) 후 "답변이 없어 종료" 안내 + 가까운 병원 안내. 시간 약속은 하지 않음 |
| 보호자 | 모르는 여러 수의사에게 질문이 노출되는 부담(개인정보) | 기본 비식별(이름·건강 메모 제외, 덧붙인 설명은 보호자가 확인), 맡은 수의사만 전체 열람, 맡기 전에는 요약만 |
| 품질 | 홍보 경쟁으로 **빠르고 짧은 답·내원 유도 답**이 늘 수 있음 | 지수는 양보다 품질(2차 검증 일치)·보호자 도움으로. 내원 권유 비율 모니터링 |
| 공정성 | 큰 병원·한가한 수의사가 요청을 독식 | 수의사별 동시 선점 수 상한, 지역 단위 노출, 오래 맡고 답 안 하면 자동 반납 |
| 수의사 | 고객 관계가 없는 보호자에게 답하는 책임 부담 | '진료가 아닌 AI 답변 검토 의견' 표시, 참여 약관 |
| 법률 | 불특정 보호자에게 수의사가 의견을 주는 구조가 **비대면 진료**로 해석될 위험이 1:1보다 클 수 있음. 공개 요청함 노출은 병원 광고 해석 여지 | 법률 검토 항목에 추가. 표현은 "AI 답변 확인"으로 한정, 진단·처방 금지 |
| 운영 | 선점·반납·기한·중복 답변 등 상태가 많아 개발·운영이 복잡 | 단계적으로: 처음에는 '먼저 맡은 1명만 답변' |

**설계 선택지**
| 선택지 | 내용 | 판단 |
|---|---|---|
| A. 선착순 1명 | 먼저 맡은 수의사 1명이 답변 | 단순, 초기 적합. 2차 검증 데이터는 별도 검토 큐로 |
| B. 여러 명 답변 | 여러 수의사가 답하고 보호자가 고름 | 데이터 풍부·경쟁 유발. 보호자 혼란·홍보 경쟁 과열 위험 |
| C. 1명 답변 + 블라인드 2차 평가 | 답은 1명, 같은 사례를 다른 수의사가 보호자 전달 없이 평가 | 보호자 경험은 A, 데이터는 B. 2차 평가는 검토 큐로 공급 |
| D. 지역·분야 배정 | 시스템이 지역·분야·지수로 몇 명에게만 보냄 | 공정성·응답률 균형. 수의사 수가 늘면 적합 |

**결정 (2026-11-15 사용자)**: 수의사 확보가 어렵다면 공개 방식이 더 쉽다 → **공개 검증 요청을 P1으로 앞당긴다.** 수의사는 보호자에게 선택받기를 기다리지 않고 자기 시간에 지역 요청을 골라 답하면 되므로 참여 장벽이 낮고, 병원에는 새 고객을 만나는 홍보 통로가 된다. P1은 **A안(먼저 맡은 1명이 답변)**으로 단순하게 시작하고, 블라인드 2차 평가(C안)는 검토 큐와 함께 P2에 붙인다. 답변 화면에 그 수의사·병원 이름과 **[이 수의사에게 주치수의사 연결 요청]**을 두어 공개 요청(획득) → 주치수의사(락인)를 잇는다. 이미 만든 주치수의사 흐름은 그대로 유지한다.

## 5. 지켜야 할 원칙

1. **보호자 신뢰 우선**: 의학 안내 영역과 병원 노출 영역을 화면에서 분리한다. 보호자가 "광고 앱"으로 느끼면 데이터도 사업도 무너진다.
2. **HITL 규칙 유지**: 원클릭 검토·지수·배지는 HITL 검증을 대신하지 않는다(신호). 수의사 참여 동의·면허 확인 후 **첫 번째 수의사 라벨**로 인정하는 길은 별도로 연다. 두 번째 수의사의 독립 재검증은 그대로 요구한다.
3. **지수 어뷰징 방지**: 하루 인정 상한, 같은 병원 수의사끼리 2차 검증 금지, 시험 계정 제외, 품질 낮으면 활동 반영 축소, 내원 권유 남발 감시.
4. **보호자 데이터**: 병원이 보호자 연락처를 직접 가져가지 않는다. 보호자가 스스로 연락·방문을 선택한다. HITL 활용은 기존 동의·운영자 정리·철회 시 삭제 규칙 그대로.
5. **표현**: 현장 수의사 평가의 가치는 인정하되 "가장 정확한 평가자", "정답" 같은 과장은 쓰지 않는다(Codex 지적).
