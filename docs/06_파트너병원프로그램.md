## 1. 한 문장 요약

> 동물병원은 **작은 수고(AI 답변 검토)**를 내고 **지역 보호자에게 실력 있는 병원으로 알려지며**, TwinVet은 그 수고로 **좋은 데이터**를 얻고, 병원의 평판·고객 관계가 TwinVet 안에 쌓이면 **락인**되어 나중에 **서비스 수수료**를 받는다.

## 2. 목적 (사용자 구상)

1. 동물병원은 **보호자(고객)에게 자기 병원을 알리기 위해** 참여한다. 병원 이름·로고를 TwinVet Care 로고 옆에 넣는다.
2. 나중에 병원에서 **서비스 수수료**를 받는다. 초반에는 **무료** 대신 **일정한 수고**를 받으며, 그 수고는 **처음에 작아야** 한다.
3. 수고한 병원은 지역사회에 **유능한 수의사로 홍보**되어야 한다. 활동을 많이(그리고 잘) 한 수의사·병원이 **검색에서 잘 나오도록** 지표를 둔다(지식인 점수 같은 것).
4. **초반에는 좋은 데이터 확보, 나중에는 락인.**

## 3. 사업 단계와 가설

| 사업 단계 | 목표 | 주치수의사의 위치 | 끝났다고 보는 기준 |
|---|---|---|---|
| **1단계 — 시험(가설 검증)** | "공개 수의사 답글이 주치수의사 확보보다 수월하고 확산 가능성이 크다"는 가설 검증, 갈 길 판단 | 공개 요청과 주치수의사 흐름을 둘 다 시험 운영해 비교 | 3-1의 지표로 판단 근거 확보 |
| **2단계 — 공개 수의사로 서비스 시작** | 공개 수의사 답글로 서비스를 열고, 공개 수의사들이 점차 주치수의사가 되며 확산 | 처음부터 요구하지 않음. **공개 요청의 결과로 생기는 관계** | 공개 요청 → 주치수의사 전환이 꾸준함 |
| **3단계 — 제품 판매·지속 데이터 파이프라인** | **PawCheck 소변검사 스티커**, **Poochnio(스마트 포티)** 판매로 건강 데이터가 계속 들어오는 구조 | **필수**. 정기 검사 결과를 같은 수의사가 이어서 확인 | 기기·스티커 데이터 → AI 해석 → 주치수의사 확인 → 보호자 안내가 반복 운영 |

- 2026-11-14에 만든 주치수의사 구조(수락, 90일 유효, 수락 전 질문 보관)는 3단계의 기반이 된다.

### 3-1. 1단계 검증 지표
| 질문 | 측정 |
|---|---|
| 수의사가 참여하는가 | 초대한 병원 중 실제로 답한 비율, 첫 답변까지 걸린 날 |
| 꾸준히 하는가 | 주별 답변 수, 4주 유지 비율, 기본 의무 달성률 |
| 보호자에게 충분한가 | 공개 요청의 24시간 내 응답 비율, '도움 됐어요' 비율 |
| 관계로 이어지는가 | 공개 요청 답변 뒤 그 수의사에게 주치수의사를 신청한 비율, 수락률 |
| 영업이 통하는가 | 신청 리드 → 메일 → 통화 → 시범 참여 전환율 |
| 데이터가 좋은가 | 검토 완료율, 보완 안내 비율, 안전 문제 지적, (P2) 2차 평가 일치율 |
| 비교 | 같은 기간 주치수의사 흐름의 연결·질문·응답률 |

- 시험은 **관리자 상담 스위치**(운영자 브라우저만 열림, 데이터는 '시험' 표시)로 시작한다. 화면·흐름은 시험수의사로 확인할 수 있지만, **가설 검증에는 실제 수의사 3~5명의 시범 참여가 필요**하다. 이들은 9장(영업)과 6-3(비파트너 병원 신청) 경로로 모은다.

## 6. 보호자가 수의사를 만나는 세 가지 길

### 6-1. 공개 검증 요청 (획득) — 1단계 P1, A안
```text
보호자: AI 답변 아래 [수의사 확인 요청] → 공유 내용 확인(질문·AI 답변·고른 반려견 정보, 기본 비식별) → 요청
  → 파트너 수의사들의 '공개 요청함'에 노출 (P1은 전국 공개 + 보호자 시·구 표시)
수의사: 요청을 맡기 → 수의사 검토(결론 + 보완 안내 + 안전 체크) → 보호자에게 전달
보호자: "○○동물병원 김수의 원장이 확인했어요" + 결론 + 보완 안내 → '도움 됐어요'
  → 마음에 들면 [○○ 원장님께 주치수의사 신청하기] (6-2로 이어짐)
24시간 안에 아무도 맡지 않으면: "답변이 없어 종료됐어요" + 가까운 병원 안내 (시간 약속 안 함)
```
- **A안(먼저 맡은 1명이 답변)**으로 시작. 맡고 오래 답하지 않으면 자동 반납, 수의사별 동시 맡기 상한.
- 맡기 전에는 요약만, 맡은 수의사만 전체 열람. 이름·건강 메모는 기본 제외.
- 블라인드 2차 평가(C안: 같은 사례를 다른 수의사가 앞 평가를 모른 채 평가, 보호자에게는 안 감)는 P2.

**장단점 정리**
| | 장점 | 단점·위험 → 대응 |
|---|---|---|
| 보호자 | 수의사를 고를 필요 없이 바로 요청 | 응답이 없을 수 있음 → 24시간 종료·병원 안내 |
| 병원 | **새 고객을 만나는 홍보 통로** | 모르는 보호자에게 답하는 책임 → "진료가 아닌 AI 답변 확인 의견" 표시·참여 약관 |
| TwinVet | 데이터가 많이·고르게, 2차 평가로 품질 지표 | 짧은 답·내원 유도 경쟁 → 지수는 품질 중심, 내원 권유 비율 감시 |
| 공정성 | | 독식 → 동시 맡기 상한, 지역 단위 노출 |
| 법률 | | 불특정 보호자 대상 의견의 비대면 진료 해석 위험이 1:1보다 큼 → 법률 검토, 진단·처방 금지 표현 |

### 6-2. 주치수의사 신청 — 파트너 수의사에게 (관계)
- **이미 있음**: 연결 요청 → 수락 = 주치수의사, 90일 유효(자동 연장 없음), 수락 전 질문 보관(거절 시 취소), 양쪽 해제, 만료 후 재신청.
- **입구**: P1 = 공개 요청 답변 아래 [주치수의사 신청하기] / 설정의 수의사 연결(현재). P2 = 수의사·병원 프로필, 병원 QR, 만료 안내의 '다시 신청하기'.
- **신청할 때 전하는 것(보호자 선택)**: 반려견 소개(품종·나이·체중·중성화 기본, 이름·건강 메모 기본 꺼짐), 한 줄 신청 말(200자, 연락처 금지 안내), 공개 요청에서 왔다면 그 대화가 근거로 붙음.
- **수의사 결정**: 수락 / 거절(사유 선택) / 7일 무응답 자동 종료(다른 수의사 추천). 수의사별 정원(예: 50명).
- **보호자 제한**: 동시 주치수의사 최대 2명.
- **역방향(P2, 선택)**: 공개 요청에 답한 수의사가 "필요하면 계속 봐 드릴게요"를 체크하면 보호자 화면에 [주치수의사로 연결하기]. 결정은 보호자.
- **3단계 연결**: PawCheck·Poochnio 등록 시 "결과를 함께 볼 주치수의사"를 고름(없으면 신청으로 연결).

### 6-3. 아직 파트너가 아닌 병원에 주치수의사 신청 → 회사가 병원에 연락 (영업 리드)
```text
보호자: 설정의 주치동물병원(공공데이터 병원) 또는 병원 찾기 → [이 병원에 주치수의사 신청]
  → 전달 범위 선택(기본: "TwinVet 이용 보호자 1명이 신청"이라는 집계만 / 반려견 소개·신청 말 포함은 선택) → 신청
  → 안내: "TwinVet이 병원에 신청을 전달하고 참여를 안내해요. 병원이 참여하면 알려 드려요." (참여·시점 약속 안 함)
회사(관리자 '파트너 영업'): 병원별 신청 리드 → 메일 발송 → 전화 상담("귀 병원에 주치수의사 신청이 들어왔습니다")
병원 참여: 시범 초대 → 쌓인 신청이 그 수의사의 '받은 신청'으로 전달 → 수락 시 주치수의사
병원 거절·무응답: 30일 뒤 신청 만료 → 보호자에게 안내 + 공개 검증 요청 권유
```
- 영업 근거가 **실제 수요**라 설득력이 크고, 병원이 참여하는 즉시 주치 관계가 생긴다(락인 시작).
- 보호자 이름·연락처는 병원에 주지 않는다. 보호자는 언제든 신청 취소.
- '연락 원치 않음' 병원은 영업 대상에서 빼고, 보호자에게 "현재 참여하지 않는 병원이에요"로 안내.

## 7. 수의사 검토와 데이터 흐름

### 7-1. 작은 수고 — 수의사 검토
- **기본 의무(제안)**: 한 달 AI 답변 **10건 검토**(건당 약 30초). 공개 요청 답변과 주치수의사 질문 검토가 모두 포함된다.
- 검토 양식: **결론 3단계 + 보완 안내(결론이 '맞아요'가 아니면 필수) + 안전 문제 체크**, 선택으로 문제 유형·한 줄 의견·"보완 안내를 개선 자료로 써도 됨" 허락.
- 문제 유형은 **AI 자동 점검기와 같은 이름**(사실 오류·빠진 경고·지나친 안심·반려견에 맞지 않음·근거와 다름)으로 맞춰 "AI 점검기와 수의사 판단의 일치율"을 측정한다.

### 7-2. 받는 곳별 결과
| 받는 곳 | 받는 것 |
|---|---|
| 보호자 | 검토한 수의사·병원 이름, 결론, 보완 안내 (AI 원답변은 접어서 함께) — **보여 줄지 최종 미결정(제안: 보여 줌)** |
| TwinVet | 결론, 안전 문제, 문제 유형, 의견, 활용 허락 범위. 보호자가 품질 개선에 동의한 경우만 내용이 HITL로(운영자 정리 → 이관, 철회 시 삭제). 동의 없으면 숫자만 |
| 수의사 본인 | 활동 기록, 받은 감사, HITL 채택·반영 결과 |

### 7-3. HITL과의 관계
- 수의사 검토·지수·배지는 **HITL 검증을 대신하지 않는다(신호)**. '다르게 봐야 해요'·'안전 문제'는 HITL 우선 검토 표시.
- 수의사 참여 동의·면허 확인 후 **첫 번째 수의사 라벨**로 인정하는 길은 P4. 두 번째 수의사의 독립 재검증은 그대로.
- 검토 큐(P2): 그 병원 보호자 질문, 동의된 질문의 정리본, AI 점검기 '자신 없음' 답변 → 보호자 수요가 적은 초반에도 데이터 확보.

## 8. 병원 노출과 동기 부여

### 8-1. 공동 브랜드
- 보호자 앱 상단 "TwinVet Care × ○○동물병원" + 로고. **그 병원과 관계 있는 보호자에게만**(P1: 그 병원 수의사가 주치수의사인 보호자 / P2: QR 유입, 그 병원을 주치동물병원으로 등록한 보호자).
- 공개 요청 답변에는 답한 수의사·병원 이름을 표시(헤더가 아니라 그 답변 카드에).
- 병원 신원은 공공데이터 동물병원(10,669곳, 영업 중 5,498곳)과 연결해 확인. `clinic.is_partner` 칸 활용.

### 8-2. 지수 (가칭 'TwinVet 케어 지수', P3에 계산)
| 요소 | 의미 |
|---|---|
| 활동 | 최근 검토·회신 수(시간이 지나면 감소, 하루 인정 상한) |
| 품질 | 2차 평가·HITL 판단과의 일치율 — 대충 누르면 떨어짐 |
| 기여 | AI 답변 개선에 실제 반영된 건수 |
| 보호자 반응 | '설명이 도움 됐어요' |
| 응답 | 공개 요청 응답률·시간 |
| 관계 | 주치 보호자 유지율(90일 뒤 재신청 비율) — 보호자에게 숫자로 노출하지 않음 |

- 1단계에서는 **재료(활동 기록)만 쌓는다.**
- 노출: 병원 찾기·수의사 목록을 **거리 + 지수**로 정렬. 보호자에게는 숫자 순위 대신 **등급과 사실**("골드 파트너", "이번 달 AI 답변 검토 32건"), **지역 단위 비교**. **'제일 유능한' 같은 최상급 표현은 쓰지 않는다**(광고 규제).

### 8-3. 동기 부여 (게이미피케이션)
- 보상 3종을 **하나의 점수로 섞지 않는다**: 활동(검토 수) / 보호자 도움(감사·도움 배지) / 지식 기여(HITL 반영·기여 배지).
- **'내 기여' 화면**과 결과 알림("선생님의 지적으로 이 답변을 개선했어요").
- '이달의 TwinVet 기여 병원·수의사'(보호자 소통 / AI 품질 개선 / 꾸준한 참여)는 실제 수의사 참여 뒤 운영자가 근거를 확인해 선정.
- 보호자 동의 여부로 수의사가 불리해지지 않게: 활동 인정과 HITL 활용 인정을 분리.
- 초기 참여 혜택: **'창립 파트너' 배지 + 무료 기간 보장(제안 1년)**.

## 9. 관리자 페이지의 '파트너 영업'

hitl-review 운영자 메뉴. 병원 발굴 → 연락 → 시범 → 파트너 전환을 한 곳에서.

| 기능 | 내용 |
|---|---|
| 영업 대상 | 공공데이터 병원 검색·지역 필터. 수요 신호 순 정렬: **주치수의사 신청 수(6-3)**, 주치동물병원 등록 수, (P2) 지역 공개 요청·미응답 수 |
| 진행 관리 | 상태: 후보 → 메일 보냄 → 통화 → 관심 → 시범 참여 → 파트너 / 거절 / 연락 원치 않음. 메모, 다음 연락일, 연락 간격 규칙 |
| 연락처 | 전화는 공공데이터에 있음. **메일 주소는 없어서** 운영자가 확인해 기록 |
| 메일 템플릿 | 신청 사실(집계), 프로그램 소개(무료·작은 수고·지역 노출·창립 파트너), 시범 참여 방법. 발송 기록 |
| 시범 초대 | 병원 계정(공공데이터 연결, `is_partner`) + 원장 수의사 계정 + **1회용 초대 링크**(열면 접근 키가 한 번 표시, 키를 메일·메신저에 적지 않음) |
| 온보딩 | 로고, 소개, 진료 분야, 첫 검토 완료, 혜택 안내 체크리스트 |
| 참여 관리(P2) | 이번 달 검토 수(의무 대비), 공개 요청 응답률, 주치 보호자 수, 최근 활동, 휴면 표시 |

- 병원에는 **집계 숫자만** 말한다. 개별 보호자·반려견 정보는 절대 전하지 않는다.

## 10. 락인과 유료 전환

- **병원 락인**: 지수·등급·배지·감사(옮길 수 없는 평판), 주치 보호자, QR 유입 고객, 내원용 상담 요약.
- **보호자 락인**: 반려견 상담 이력, 주치수의사, (3단계) 검사·기기 데이터.
- **유료 전환(P4)**: 기본 참여(검토·노출 자격)는 무료 유지 → 데이터 공급이 끊기지 않게. 유료는 공동 브랜드 유지, 지역 상위 노출 **강화**, 월간 성과 리포트(노출·전화·지도 클릭·주치 신청), QR 고객 관리.
- **노출 자격은 품질로만** 결정. 유료는 강화만, 품질 기준 미달이면 유료여도 노출 안 함.

## 11. 지켜야 할 원칙

1. **보호자 신뢰 우선**: 의학 안내 영역과 병원 노출 영역을 화면에서 분리. "광고 앱"으로 느끼면 데이터도 사업도 무너진다.
2. **HITL 규칙 유지**: 수의사 검토·지수·배지는 검증을 대신하지 않는다(7-3).
3. **어뷰징 방지**: 하루 인정 상한, 같은 병원 수의사끼리 2차 평가 금지, 시험 계정 제외, 품질 낮으면 활동 반영 축소, 내원 권유 남발 감시.
4. **보호자 데이터**: 병원이 보호자 연락처를 직접 가져가지 않는다. 기본 비식별, 보호자가 전달 범위를 정함. HITL 활용은 동의·운영자 정리·철회 시 삭제.
5. **약속하지 않기**: 응답 시간·병원 참여를 약속하지 않는다. 응급은 언제나 동물병원 안내로.
6. **과장 표현 금지**: "가장 정확한 평가자", "정답", "제일 유능한" 같은 표현을 쓰지 않는다.

## 12. 법률 검토 항목 (수의사 상담 스위치를 켜기 전)

- 공개 검증 요청: 불특정 보호자에게 수의사가 의견을 주는 구조의 비대면 진료 해당 여부, 공개 요청함 노출의 광고 해당 여부
- 병원 이름·로고 노출, 지수 기반 정렬·등급 표시의 수의 광고 해당 여부
- 수의사 검토 결과의 보호자 노출 표현
- 비파트너 병원 신청: 신청 사실·반려견 소개를 병원에 전하는 것의 동의 문구, 병원 연락(메일·전화) 방식
- 영업에 집계 숫자(신청·등록 수)를 쓰는 것의 약관·개인정보 처리방침 반영
- 수의사·병원 참여 약관(검토·회신의 서비스 개선 활용, 이름 표시), 보호자 동의 문구
- 수수료 구조와 유료 노출의 고지

## 13. 개발 단계

사업 단계와의 관계: P1·P2 = 1단계(시험), P3 = 2단계 시작, P4 = 2단계 확산·3단계 준비. 모든 신규 기능은 먼저 **관리자 상담 스위치(시험 모드)** 안에서 동작한다.

| 단계 | 내용 |
|---|---|
| **P1 — 1단계 시험에 필요한 것** | ① 파트너 병원 계정(공공데이터 연결, 이름·로고·소개)과 수의사의 병원 소속 ② **주치수의사 신청**: 파트너 수의사에게(신청 말·소개, 7일 자동 종료, 보호자 최대 2명, 수의사 정원) + **비파트너 병원 신청 → 영업 리드**(30일 만료) ③ **관리자 '파트너 영업'**: 병원 검색, 신청 리드, 상태·메모, 메일 템플릿, 1회용 시범 초대 링크 ④ **공개 검증 요청 A안**(24시간 기한, 맡기·자동 반납) ⑤ **수의사 검토 양식**(결론·보완 안내·안전 체크) ⑥ 답변 카드에 수의사·병원 이름 + 주치수의사 신청 버튼 ⑦ 활동 기록·'내 기여' 기본 ⑧ 공동 브랜드(주치수의사 관계만) |
| **P2** | 블라인드 2차 평가(C안)·검토 큐, 병원 QR 유입, 보호자 '도움 됐어요·감사해요', 프로필·만료 안내 입구, 역방향 제안, 영업 참여 관리, 공동 브랜드 확대 |
| **P3** | 지수 계산·등급·배지, 거리 + 지수 정렬, 월간 성과 리포트, AI 점검기와 수의사 판단 일치율 |
| **P4** | 유료 전환, 수의사 검토를 첫 번째 HITL 라벨로 인정(참여 동의·면허 확인), 이달의 기여 병원 |
| **하지 않음** | 공개 순위표, 현금 보상, 자동 종합점수 공개 |

**P1 안의 순서(제안)**: ①·② 비파트너 신청·③ 영업(실제 수의사를 모으는 길이 먼저 열림) → ④·⑤·⑥ 공개 검증 요청과 검토 → ⑦·⑧.
