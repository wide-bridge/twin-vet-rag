# TwinVet Care 서비스 기획서

버전: 0.4 · 작성일: 2026-11-09 · 상태: 개발 검토용 초안 (0.4: 생애주기 선택 → 반려견 품종·나이·건강상태 입력, 사용자 확정)

## 1. 목적과 역할

반려견 보호자가 상담 자료를 근거로 질문에 대한 정보를 얻고 후속 질문을 이어갈 수 있는 서비스를 만든다.

- PM: 범위·사용자흐름·데이터·기능·화면·완료 기준 정의.
- Claude Code: 개발자 관점의 문서 검토, 확정 스택에 따른 구현·테스트·배포. Codex는 PM으로 단계별 결과를 검토한다.
- 기존 TwinVet 기획 자료는 참고 자료다. 기존 기능·수치·일정을 이번 요구사항으로 자동 적용하지 않는다.
- GitHub: https://github.com/wide-bridge/twin-vet-rag — 확인 시점에는 README와 .gitignore만 존재한다.

## 2. 단계별 범위 — 사용자 확정

| 단계 | 범위 | 완료 결과 |
|---|---|---|
| PoC | 일반 RAG 기반 서비스. 디자인·DB·백엔드/API·프론트엔드·통합 테스트·배포 포함 | 실제 사용 흐름을 갖춘 배포 가능한 상담 서비스와 평가 결과 |
| MVP | PoC에 지식그래프 또는 온톨로지, 수의사 HITL 추가 | 구조화된 지식 활용과 수의사 검토가 연결된 서비스 |

PoC는 단순 실험 스크립트에 그치지 않는다. MVP는 두 기능을 추가하는 단계이며, PoC 구현의 재사용 여부는 개발 검토에서 판단한다.

## 3. PoC 기능 — PM 제안 기본안

반려견 고정, 반려견 정보 입력(품종·나이·건강상태), 데이터 구분, 개발 스택은 확정 기준이다. 익명 세션·이력·피드백 등 나머지 세부 기능은 기존 PM 기본안이며 개발 검토 대상이다.

| ID | 기능 | 범위 |
|---|---|---|
| P01 | 상담 시작 | 로그인 없이 익명 세션으로 시작. 반려견 고정. 반려견 정보(이름 선택, 품종·나이 필수, 건강상태 선택) 입력 후 질문 |
| P02 | RAG 상담 | 질문과 필요한 대화 맥락을 이용해 검색·답변 생성 |
| P03 | 근거 확인 | 답변에 연결된 문서명·출처 표시. 원문 발췌는 이용 조건 확인 전 비활성화 |
| P04 | 후속 질문·현재 대화 | 현재 세션에서 질문을 이어가고 대화 확인 |
| P05 | 피드백 | 답변별 도움 여부와 선택적 의견 수집 |
| P06 | 지식 데이터 관리 | 운영자가 명령 또는 스크립트로 적재·재색인·비활성화 |
| P07 | 예외·운영 | 근거 부족·범위 밖 질문·장애 안내, 로그·기본 모니터링 |

PoC 기본안에서 제외: 회원가입, 반려견 외 동물(고양이 등), 상담 간 재사용·저장되는 반려견 프로필(정보는 상담 단위로만 입력), 여러 기기의 상담 동기화, 이미지·영상 상담, 병원 예약, 결제, 수의사 검토 화면, 지식그래프/온톨로지, 센서 연동. 필요하면 범위를 명시적으로 변경한다.

## 4. MVP 추가 기능

| ID | 기능 | 설계 방향 |
|---|---|---|
| M01 | 지식그래프 또는 온톨로지 | 개념·관계·조건을 정의하고 질의 결과를 RAG 근거와 함께 활용 |
| M02 | 수의사 HITL | 검토 요청 → 배정 → 수정·승인 또는 추가 질문 → 보호자 결과 확인 |

수의사 검토를 받지 않은 답변을 검토 완료로 표시하지 않는다. 검토 대상 조건, 운영 시간, 응답 목표, 참여 수의사 확보는 MVP 착수 때 결정한다. 모든 답변 사전 승인 여부는 미확정이다.

## 5. 서비스 원칙과 완료 기준

- 상담 정보 제공 목적을 명확히 표시하고 확정 진단·처방을 서비스 기능으로 제공하지 않는다.
- 검색 근거가 없으면 그 사실을 알리고 추가 정보 또는 전문가 상담을 안내한다.
- 응급 상황은 AI 답변을 기다리지 않고 동물병원에 바로 연락하도록 **고정 안내**를 시작·상담 화면에 항상 표시한다. AI가 응급 여부를 판정하지 않는다.
- 상담 원문은 공용 지식 검색 대상에 자동 편입하지 않는다.
- PoC 완료: P01~P07 흐름 구현, 다른 세션 접근 차단, 실패 상태 표시, 데이터 변경 반영, 배포 환경에서 핵심 테스트 통과.
- 평가: 대표 질문·근거 부족·범위 밖·후속 질문·장애 사례로 검색 적절성, 근거 일치, 응답시간, 호출 비용을 측정한다. Validation 2,400건을 색인에서 제외하고 고정 평가 질문·정답 세트로 사용한다. 개발 평가군과 최종 검증군을 분리하고 Training 중복을 검사한다. 통과 목표는 구현 전 정하며 원천 정답 일치와 상담 안전성은 별도 평가한다. 측정 전 수치를 성과로 기재하지 않는다.
- MVP 완료: M01·M02 통합 후 동일 질문 세트로 일반 RAG 대비 효과와 수의사 검토 결과를 확인한다.

## 6. 구현 전에 결정할 사항

1. 반려견 내 상담 주제의 범위, 아래 데이터의 사용 조건, 개인정보 처리.
2. 답변 생성 LLM·배포 대상·예산. 확정 스택: 기존 Conda `smart_tour`, FastAPI, PostgreSQL 16+pgvector, React + TypeScript + Vite, OpenAI `text-embedding-3-small`. 새 가상환경은 만들지 않는다.
3. 익명 세션 기본안 채택 여부, 보관 기간·삭제 방식, 평가 기준.

다섯 문서의 공통 기능 ID를 유지한다. 변경은 해당 문서에 반영하며 별도의 관리 문서를 늘리지 않는다.

## 8. 이번 확정 사항

- 동물 선택 UI·종 필드를 두지 않고 반려견만 지원한다.
- 생애주기 선택 UI는 두지 않는다. 대신 보호자가 **이름(선택)**, **품종·나이(필수)**와 **건강상태(선택: 체중, 중성화 여부, 기존 질환·복용 약)**를 입력하고, 서비스가 이를 답변 판단에 사용한다.
  - 생애주기(자견·성견·노령견)는 나이에서 서버가 산출해 검색 필터로 쓴다(산출 생애주기 OR 공통 OR 미지정 자료).
  - 품종·나이·건강상태는 검색 질의 구성과 답변 맥락에 반영한다. 보호자 입력값이며 검증된 의료 기록이나 진단 근거로 취급하지 않는다.
  - 품종별·건강상태별 주의사항은 검색 근거가 있을 때만 언급한다. 근거 없는 품종 일반화를 하지 않는다.
- 고양이 등 반려견 외 동물 질문은 지원 범위 밖으로 안내한다. 59번 질의응답 21,606건 중 고양이 상담은 1건뿐임을 전수 확인했다.
- 지식은 `qa_case`(사례 1건=청크 1개), `reference`(교재·논문 절·문단 분할)로 구분한다. 진료과·질병명·생애주기 메타데이터를 보존한다.
- 원천 교재·학술지의 검색·생성 활용 및 원문 노출 조건을 공개 배포 전에 확인한다. 짧은 발췌도 허용된 것으로 가정하지 않으며 확인 전 문서명·출처만 표시한다.
- 문서는 `docs/`의 5종만 유지한다. 구현 실행법은 README에 기록하고 별도 관리 문서를 늘리지 않는다.
- 개발 순서: 문서 반영 → 환경 구성 → 데이터·RAG → API·화면 → 통합 테스트·배포. 단계별 커밋과 변경 요약·테스트 결과·미해결 사항·커밋 ID를 Codex PM에게 보고한다.

화면에는 입력한 나이(예: 10세 3개월)만 표시하며 생애주기 명칭·나이 구간은 표시하지 않는다. 품종·체중 등 기존 정보 표시는 유지한다. 생애주기는 내부 검색에만 사용한다.
