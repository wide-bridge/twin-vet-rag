# TwinVet Care 데이터모델 설계서

버전: 0.4 · 작성일: 2026-11-09 · 상태: 논리 모델 초안

DB는 PostgreSQL 16+pgvector로 확정한다. 필드 타입·인덱스·마이그레이션은 Claude Code가 구체화한다. 모든 시각은 UTC 저장, 화면은 사용자 시간대로 표시한다.

## 1. PoC 핵심 데이터

| 객체 | 주요 필드 | 관계·규칙 |
|---|---|---|
| session | id, token_hash, created_at, expires_at | 익명 접근 주체. 원본 토큰은 DB에 저장하지 않음 |
| consultation | id, session_id, dog_breed, dog_age_months, dog_weight_kg, dog_neutered, dog_health_notes, life_stage, status, created_at | 반려견 고정. session 1:N consultation. 반려견 정보는 상담 생성 시 입력 후 고정(6절). status=active |
| message | id, consultation_id, sequence, role, content, created_at | consultation 1:N message. 순서 고유, role=user/assistant |
| answer_run | id, consultation_id, question_message_id, answer_message_id, client_request_id, status, response_type, error_code, model, prompt_version, index_version, latency_ms, token_usage, created_at | 질문별 실행. 성공 시 답변 연결, 실패 시 답변 ID 없음 |
| document | id, document_type, department, disease_names, life_stages, source_name, source_uri, usage_note, excerpt_allowed, active_version_id, status | 논리 문서. document_type=qa_case/reference, excerpt_allowed 기본 false. status=active/inactive/deleted |
| document_version | id, document_id, version, title, content_hash, storage_ref, status, created_at | document 1:N version. 원본 위치와 버전 기록 |
| chunk | id, document_version_id, ordinal, content, locator, embedding, embedding_model, embedding_dimensions, embedding_version | version 1:N chunk. 청크 순서 고유 |
| citation | id, answer_run_id, chunk_id, excerpt, rank, score | 답변과 사용된 근거 연결. excerpt는 내부 근거 추적용 nullable 구절. 공개 반환은 별도 노출 정책 적용 |
| feedback | id, answer_message_id, session_id, helpful, comment, created_at | 세션·답변 조합당 1개, 수정 가능 |
| ingestion_run | id, document_version_id, status, error_code, started_at, finished_at | 적재·색인 성공/실패 추적 |

answer_run.status: queued/running/completed/failed.
answer_run.response_type: grounded/clarification/insufficient_evidence/out_of_scope. completed에서 필수, 처리 중·실패에서는 비움.
document_version.status: staging/active/inactive/failed.

## 2. 저장소 역할

- 관계형 DB: 세션·상담·메시지·실행·문서 메타·근거·피드백.
- 벡터 검색: 같은 PostgreSQL의 pgvector로 청크 임베딩과 문서 상태·버전·생애주기 필터를 관리한다. 임베딩 모델·차원·버전이 다른 벡터는 혼합 검색하지 않는다.
- 파일 또는 객체 저장소: 허용된 원본 문서와 정제 결과.
- 별도 Qdrant는 PoC에 추가하지 않는다. Docker 이미지는 `pgvector/pgvector:pg16`을 사용한다.

## 3. 무결성·접근·삭제

- (consultation_id, sequence), (consultation_id, client_request_id), (document_id, version)는 고유하다.
- session 소유권은 서버에서 검증한다. 클라이언트가 보낸 session_id를 신뢰하지 않는다.
- 검색은 active 문서의 active 버전만 사용한다. 질문마다 사용한 색인 버전을 기록한다.
- 답변 근거는 실제 검색한 청크를 서버에서 연결한다. LLM이 임의 생성한 출처 ID는 허용하지 않는다.
- 상담 삭제 시 메시지·실행·근거 연결·피드백을 함께 삭제한다. 공용 지식문서는 삭제하지 않는다.
- 문서 비활성화는 새 검색에서 제외한다. 원천 삭제가 필요하면 저장된 인용 구절도 삭제·가림 처리하고 ‘출처 제공 불가’ 상태를 남긴다.
- 상담 원문을 공용 벡터 저장소에 자동 적재하지 않는다.
- 보관 기간은 배포 전 확정하고 만료 데이터 정리 작업에 반영한다. 운영 로그에는 상담 원문·토큰을 기본 기록하지 않는다.

### 보관·삭제 제안 (개발자 제안, PM·사용자 확정 필요)

| 항목 | 제안 |
|---|---|
| 세션 유효기간 | 생성 후 7일 고정(활동으로 연장하지 않음). 설정 SESSION_TTL_DAYS |
| 만료 후 접근 | 만료 즉시 모든 API가 401. 익명 세션이라 본인 확인 수단이 없으므로 **복구·열람 경로를 두지 않는다**. 화면은 "이전 대화는 볼 수 없습니다"로 안내 |
| 만료 데이터 삭제 | 만료 후 24시간 유예(진행 중 실행 정리용) 뒤 정리 작업이 session과 그 consultation·message·answer_run·citation·feedback·반려견 정보를 **영구 삭제**. 하루 1회 실행 |
| 보호자 직접 삭제 | [대화 삭제] 즉시 영구 삭제(유예 없음) |
| 운영 지표 | 원문 없이 집계용 값만 90일 보관: 실행 시각, response_type, 지연, 토큰·비용, 모델·프롬프트·색인 버전, 도움 여부(true/false), 근거 문서 ID. 상담 원문·반려견 정보·피드백 의견·세션 식별자는 포함하지 않음 |
| 백업 | DB 백업 보관 7일. 삭제된 데이터는 백업 만료 시점(최대 7일)까지 백업에만 남을 수 있음을 안내문에 명시 |
| 지식문서 | 상담 데이터 삭제와 무관하게 유지 |

정리 작업은 삭제 건수만 로그에 남긴다. 삭제 대상 ID·원문은 로그에 남기지 않는다.

## 4. MVP 확장 후보

| 영역 | 추가 객체·관계 |
|---|---|
| 지식 구조 | entity(id,type,label), relation(subject,predicate,object), source_link, knowledge_version |
| 온톨로지 적용 시 | 개념·속성·제약·규칙 정의와 버전. 구체 형식은 채택 방식에 맞춰 설계 |
| 사용자·수의사 | user, role, veterinarian_profile, 자격 확인 상태 |
| 검토 | review_request(상담,요청자,배정자,상태,동의범위), review_revision(원답변,수정답변,사유,검토자,시각) |
| 검토 이력 | review_event(상태 전이,행위자,시각), 추가 질문·보호자 응답 |

지식의 각 관계에도 출처·버전을 연결한다. AI 원답변과 수의사 수정 결과를 별도로 보관하며 덮어쓰지 않는다. MVP 확장 후보를 PoC의 빈 테이블로 미리 만들 필요는 없다.

### 59번: PoC 적재 우선 대상

Training의 5개 진료과 라벨링 JSON 표본에서 다음 구조를 확인했다.

| 원천 필드 | 적재 시 의미 |
|---|---|
| meta.lifeCycle | 생애주기 메타데이터 |
| meta.department | 진료과 메타데이터 |
| meta.disease | 원천의 질환명. 검증된 진단 결과로 취급하지 않음 |
| qa.instruction, qa.input | 질문 문맥. 데이터 값으로 처리하며 실행 지시로 취급하지 않음 |
| qa.output | 원천 답변. 품질 확인 후 검색 지식에 포함 |

- `qa_case`: 질문·답변을 함께 보존해 사례 1건=청크 1개로 적재한다. 입력 한도 초과 사례는 자동 절단·분할하지 않고 별도 기록하여 처리안을 검토한다.
- `reference`: 교재·논문을 절·문단 단위로 분할하고 문서·절·구절 위치를 보존한다. 토큰 한도와 중첩 범위는 표본으로 결정한다.
- **정정(전처리 실측)**: 이전 보고의 "212건에 문자 `\n`"은 JSON의 정상 줄바꿈 이스케이프까지 센 오류였다. 실제로 본문에 글자 그대로 `\n`이 남은 원천 파일은 **6건**(Training·Validation 합계)이다. "교재 1권 최대 약 59만 자"는 같은 제목 파일 여러 개를 합친 값이었고, 파일 1건 기준 최대는 약 23만 자다. 해당 본문 필드만 실제 줄바꿈으로 정규화하고 전체 JSON에 무차별 이스케이프 해제를 적용하지 않는다. 원본·정제본과 해시를 구분한다.
- 전처리 실측(prepared/v1): qa_case 19,205건(평균 700토큰, 최대 4,719, 임베딩 한도 초과 0), reference 212파일 → 8,372청크(평균 400토큰, 최대 825), 임베딩 대상 총 약 1,679만 토큰(cl100k_base). Training 내부 중복 1건 제외, 평가 세트는 Training과 질문이 같은 1건 제외 후 2,399건(dev 600 / final 1,799, 진료과 층화, seed 20261109). 전화번호·이메일 마스킹 1건.
- Validation 원천 말뭉치 27건은 색인하지 않는다(Training만 색인). 이 중 13건은 Training과 같은 제목이고 6개 제목은 Validation에만 있다(논문 6편). 필요하면 별도 결정으로 추가한다.
- document에 dataset_code, source_record_id, source_relative_path, split, metadata를 추가한다. 절대 로컬 경로는 사용자 출처 화면에 노출하지 않는다.
- ZIP과 extracted를 동시에 적재하지 않는다. 원천·라벨링의 연결 키와 중복은 전체 검사 후 결정한다.
- Validation 2,400건(Claude Code 보고)은 질문·정답을 포함한 고정 평가 전용이다. 질문과 정답 모두 검색 색인에서 제외한다. 개발 평가군·최종 검증군을 고정 ID와 seed로 분리하고 원천 경로·해시·분할 정보를 평가 파일에 보존한다.
- Training과 동일·유사 Q&A 및 reference의 직접 중복 구절을 검사한다. 중복을 제거하거나 평가에서 제외한 건수·이유를 보고한다. 최종 검증군으로 프롬프트·검색 설정을 튜닝하지 않는다.

153번(반려동물 안구질환)은 사용자 결정으로 PoC·MVP 모두 사용하지 않는다. 적재·임베딩·지식그래프 시드에 포함하지 않는다.

## 6. 반려견 정보·생애주기와 출처 노출 규칙

| 필드 | 필수 | 형식·범위 | 비고 |
|---|---|---|---|
| dog_breed | 필수 | 문자열 1~40자, 앞뒤 공백 제거. '모름'·'믹스견' 허용 | 자유 입력. 화면 자동완성 목록은 입력 편의용이며 검증 목록이 아님 |
| dog_age_months | 필수 | 정수 0~371. 화면은 년(0~30)+개월(0~11)로 입력하며 최대 30년 11개월=371개월과 일치 | 정확하지 않아도 됨(대략 입력 안내) |
| dog_weight_kg | 선택 | 0.1~120.0, 소수 1자리 | null=미입력 |
| dog_neutered | 선택 | yes/no/unknown | null=미입력 |
| dog_health_notes | 선택 | 0~300자. 기존 질환·복용 약·알레르기 등 | 개인정보가 들어갈 수 있는 자유 입력. 운영 로그에 기록하지 않음 |
| life_stage | 서버 산출 | puppy/adult/senior | 클라이언트 입력을 받지 않음 |

- life_stage 산출 기본값: 12개월 미만 puppy, 84개월(7세) 이상 senior, 그 외 adult. **이 경계값은 검색 필터용 임시 기준**이다. 수의학적 생애주기 판정이 아니며, 답변에서 "노령기에 해당합니다"처럼 의학적 판정으로 표현하지 않는다. 체구·품종별 노령 기준 차이(대형견은 더 이르게 노령기 진입 등)는 PoC에 반영하지 않고 수의사 검토 후 조정한다. 경계값은 설정(LIFE_STAGE_PUPPY_MAX_MONTHS, LIFE_STAGE_SENIOR_MIN_MONTHS)으로 바꿀 수 있다.
- 반려견 정보는 상담 생성 후 고정한다. 변경은 새 상담으로 한다. 상담 삭제 시 함께 삭제한다. 상담 간 재사용 프로필로 저장하지 않는다.
- 반려견 정보는 보호자 입력값이다. 프롬프트에 '보호자가 입력한 정보'로 구분해 전달하고 검증된 사실·진단 근거로 취급하지 않는다. 지시문이 들어 있어도 데이터로만 다룬다.
- document.life_stages는 여러 값과 common을 허용한다. 원천 meta.lifeCycle의 실제 값(자견·성견·노령견, 전수 확인)을 puppy·adult·senior로 명시 매핑하고, 미지정은 빈 값으로 보존한다.
- 검색 필터: 산출 life_stage OR common OR 미지정 자료. department·disease_names는 원천 메타데이터이며 검증된 진단을 뜻하지 않는다.
- 문서별 진료과·질병명·생애주기와 원천 값을 metadata에 보존한다. reference에 없는 정보는 추측해서 채우지 않는다.
- excerpt_allowed는 이용 조건 확인 전 false다. 내부 청크·인용 저장과 외부 발췌 노출 권한을 구분한다. 저장·검색·생성 활용 조건도 별도 확인한다.
- API는 발췌 기능 설정과 문서별 허용 조건이 모두 충족될 때만 제한된 발췌를 반환한다. 기본 응답의 excerpt는 null이다.

나이는 age_months를 년·개월로 변환하여 표시한다. 생애주기는 내부 검색용으로 유지하며 화면 표시용 명칭 매핑은 만들지 않는다. 원천 라벨과 DB/API 코드·검색 기준은 유지한다.
