# TwinVet Care 데이터모델 설계서

버전: 0.6 · 작성일: 2026-11-09 · 상태: 논리 모델 초안 (0.5, 2026-11-12: dog_profile·clinic·상담 요약 추가 / 0.6, 2026-11-13: MVP1 온톨로지·검토·지식 후보)

DB는 PostgreSQL 16+pgvector로 확정한다. 필드 타입·인덱스·마이그레이션은 Claude Code가 구체화한다. 모든 시각은 UTC 저장, 화면은 사용자 시간대로 표시한다.

consultation.topic: 첫 질문의 주제 1개(ear/eye/skin/oral/digestive/urinary/respiratory/other — 2026-11-12 확정). topics: 상담 중 나온 주제 최대 3개. 질문 분류 단계에서 함께 산출(추가 호출 없음).
consultation.summary: AI 요약 2줄 이내(보호자가 말한 증상 + AI 안내 요지, 진단 표현 금지). 케어에서 처음 볼 때 생성해 저장하고, summary_turns(요약 당시 메시지 수)보다 대화가 늘면 다시 생성한다. 같은 날 같은 주제 묶음의 통합 요약은 저장하지 않고 [병원에 보여주기]를 누를 때 만든다.

answer_run.status: queued/running/completed/failed.
answer_run.response_type: grounded/clarification/insufficient_evidence/out_of_scope. completed에서 필수, 처리 중·실패에서는 비움.
document_version.status: staging/active/inactive/failed.

## 2. 저장소 역할

- 관계형 DB: 세션·상담·메시지·실행·문서 메타·근거·피드백.
- 벡터 검색: 같은 PostgreSQL의 pgvector로 청크 임베딩과 문서 상태·버전·생애주기 필터를 관리한다. 임베딩 모델·차원·버전이 다른 벡터는 혼합 검색하지 않는다.
- 파일 또는 객체 저장소: 허용된 원본 문서와 정제 결과.
- 별도 Qdrant는 PoC에 추가하지 않는다. Docker 이미지는 `pgvector/pgvector:pg16`을 사용한다.

## 3. 무결성·접근·삭제

- (consultation_id, sequence), (consultation_id, client_request_id), (document_id, version)는 고유하다.
- session 소유권은 서버에서 검증한다. 클라이언트가 보낸 session_id를 신뢰하지 않는다.
- 검색은 active 문서의 active 버전만 사용한다. 질문마다 사용한 색인 버전을 기록한다.
- 답변 근거는 실제 검색한 청크를 서버에서 연결한다. LLM이 임의 생성한 출처 ID는 허용하지 않는다.
- 상담 삭제 시 메시지·실행·근거 연결·피드백을 함께 삭제한다. 공용 지식문서는 삭제하지 않는다.
- 문서 비활성화는 새 검색에서 제외한다. 원천 삭제가 필요하면 저장된 인용 구절도 삭제·가림 처리하고 ‘출처 제공 불가’ 상태를 남긴다.
- 상담 원문을 공용 벡터 저장소에 자동 적재하지 않는다.
- 보관 기간은 배포 전 확정하고 만료 데이터 정리 작업에 반영한다. 운영 로그에는 상담 원문·토큰을 기본 기록하지 않는다.

## 4. MVP1 데이터 (2026-11-13, M01·M02)

같은 Neon DB 안에서 다음 4개 영역을 논리적으로 구분한다. **RAG 검색 대상은 '배포 지식'뿐이다.**

| 영역 | 테이블 | RAG 검색 |
|---|---|---|
| 상담 기록 | consultation·message·answer_run·citation (1절) | 제외 |
| 검토 기록 | review_item·review_label·label_concept·review_event | 제외 |
| 지식 후보 | knowledge_candidate | 승인·활성화 전 제외 |
| 배포 지식 | document·document_version·chunk (활성 버전만) | 포함 |

| 객체 | 주요 필드 | 관계·규칙 |
|---|---|---|
| reviewer | id, role(vet/operator), display_name, email?, credential_status(unverified/verified), access_key_hash, active, created_at, last_login_at | 수의사·운영자. 원본 접근 키는 저장하지 않음(해시만). 수의사 자격 확인 전에는 unverified. A단계에는 운영자만 발급 |
| reviewer_session | id, reviewer_id, token_hash, created_at, expires_at | 작업 화면 로그인. 보호자 익명 세션과 별개 |
| concept | id, scheme, code, label, synonyms[], definition, status(draft/approved/retired), version, source_note, created_at, updated_at | 온톨로지 개념. scheme = topic/body_part/symptom/condition/test/observation/action. (scheme, code) 고유. 수의사 확정 전에는 draft |
| concept_relation | id, subject_id, predicate, object_id, conditions(jsonb), source_note, status, version | predicate = is_a/part_of/located_in/associated_with/red_flag_for/recommends. conditions에 생애주기·품종·기간 등 적용 조건 |
| review_item | id, origin(dataset/mock/consultation), is_mock, source_ref, question, history(jsonb), dog(jsonb), ai_answer, response_type, citations(jsonb), versions(jsonb: model·classifier·prompt·index), content_hash, review_status, dispute_type?, created_at, updated_at | 검토 묶음. 생성 시점 복사본으로 고정. (origin, source_ref) 고유. review_status = draft/vet_reviewed/independently_verified/disputed, dispute_type = info_lacking/evidence_conflict/acceptable_difference. origin=mock ⇔ is_mock |
| review_label | id, item_id, author_kind(vet/operator/ai), reviewer_id?, state(draft/submitted), ai_suggestion_shown, accuracy, evidence_support, sufficiency, guidance, safety_issue, revised_answer?, revision_reason?, revision_evidence(jsonb), reuse_scope, note?, started_at, submitted_at?, active_seconds? | 라벨 1건. 작성자당 묶음 1건(ai는 묶음당 1건). 값: accuracy = appropriate/minor_edit/inappropriate/undeterminable, evidence_support = supported/partial/unsupported, sufficiency = answerable/needs_more_info, guidance = appropriate/missing_important/inappropriate, reuse_scope = case_only/conditional/general_candidate/excluded |
| label_concept | label_id, concept_id, assertion | 라벨의 개념 태그. assertion = owner_reported/ai_inferred/vet_assessed/test_confirmed. 같은 개념에 여러 출처를 함께 기록할 수 있음(복수 행) |
| review_event | id, item_id, actor_kind(vet/operator/ai/system), reviewer_id?, event, detail(jsonb), created_at | 상태 전이·제출·이견·조정 이력. 덮어쓰지 않음 |
| knowledge_candidate | id, item_id?, label_id?, kind(case/general), title, content, conditions(jsonb), evidence(jsonb), content_hash, is_mock, publish_status, approved_hash?, approved_by?, approved_at?, eval_result(jsonb)?, document_id?, created_at, updated_at | 지식 후보. publish_status = unapproved/approved/active/rejected/retired. 승인은 approved_hash(=승인 당시 content_hash)에 묶이며 내용이 바뀌면 unapproved로 돌아감. 활성화는 기존 적재 흐름(7절)으로 document(dataset_code=vetreview)를 만든다 |

규칙:

- **검토 상태는 라벨에서 계산한다.** 제출된 vet 라벨 1건 → vet_reviewed, 서로 다른 vet 2명 이상이 제출하고 선택 항목 전체(accuracy·evidence_support·sufficiency·guidance·safety_issue·reuse_scope)가 일치 → independently_verified, 하나라도 다르면 disputed(유형은 조정 때 기록). 수정안·수정 사유·개념 태그는 자동 비교하지 않고 지식 후보 작성·승인 때 맞춘다. operator·ai 라벨은 검토 상태를 바꾸지 않는다.
- **발행 승인 조건**: 후보의 출처 묶음이 independently_verified, reuse_scope가 conditional 또는 general_candidate, 승인자는 후보를 작성·수정하지 않은 vet(review_event의 candidate_created·candidate_updated 기록으로 판정). 묶음을 라벨링한 두 번째 수의사도 승인할 수 있어 수의사 2명으로 운영된다. C단계 전에는 시험 환경의 operator가 모의 후보만 승인할 수 있다. **활성화 조건**: approved_hash = content_hash, 같은 해시·같은 임베딩 모델의 검색 영향 점검이 유효하고 통과, is_mock이면 운영 환경에서 거부. 실제 후보의 점검은 질문 30개 이상이 비교 가능해야 유효하고, 모의 흐름 결과(search_impact(mock_flow))는 실제 후보에 쓸 수 없다.
- **적용 조건 전달**: conditions는 발행 본문 끝에 '적용 조건: … 이 조건에 해당할 때만 적용한다.'로 들어간다. 검색 결과에는 별도 구조화 필드가 없으므로 본문이 답변 모델까지 조건을 전달한다. life_stages는 검색 필터에도 반영한다.
- 자동 점검(제출 시): 필수 항목 누락, accuracy가 minor_edit/inappropriate인데 수정안·사유 없음, reuse_scope가 general_candidate인데 근거 없음, draft·retired 개념 코드 사용, 모순 조합(예: accuracy=appropriate인데 guidance=inappropriate) → 422.
- AI 원답변과 수의사 수정안을 따로 보관하며 덮어쓰지 않는다. 독립 라벨링 중에는 같은 묶음의 다른 vet 라벨을 제출 전까지 보여 주지 않는다.
- 보관: dataset·mock 묶음은 개인정보가 없어 상담 보관 기간(7일)과 무관하게 유지한다. consultation 묶음은 별도 동의·비식별화·보관 기간 확정 전에는 만들지 않는다.
- 분할표: `DATA_OUTPUT_DIR/prepared/<버전>/split_table.jsonl`에 source_record_id·split·department·dup_group·fold(고정 seed, 중복 그룹은 같은 fold)를 기록한다. 지식 반영·라벨링 사용 이력은 review_item.source_ref로 추적한다.

| 이후 확장 (MVP1 밖) | 추가 객체·관계 |
|---|---|
| 보호자 대상 수의사 답변(M03) | review_request(상담,요청자,배정자,상태,동의범위), 추가 질문·보호자 응답 |
| 보관 기간 전환 (검토안) | 계정이 생기면 익명 프로필을 가입 계정으로 옮기고(owner_user_id) expires_at을 null(계정 유지 동안 보관)로 바꾼다. 상담 기록 장기 보관은 별도 보관 동의(선택)를 받은 경우에만. 탈퇴·삭제 요청 시 즉시 삭제, 장기 미이용 처리·백업 보관·내보내기는 법령 확인 후 정한다. 데이터 종류(상담 원문·요약·프로필·병원)별로 기간을 따로 둔다 |

지식의 각 관계에도 출처·버전을 연결한다. 이후 확장 객체를 빈 테이블로 미리 만들지 않는다.

## 7. 데이터 처리 파이프라인 (구현 기준, 2026-11-09)

원천 → 정제 파일 → DB 색인 → 검색의 4단계로 처리한다. 각 단계는 다시 실행해도 결과가 같고(멱등), 실패해도 현재 검색 중인 색인을 바꾸지 않는다.

```text
[원천] D:\ai_hub_data\59...\extracted (읽기 전용)
  │ ① 정제  python -m scripts.prepare_data --version v1      (네트워크·비용 없음)
  ▼
[정제 파일] data_output/prepared/v1/  qa_cases · reference_docs · reference_chunks · eval_dev · eval_final · excluded · report
  │ ② 적재  python -m scripts.load_knowledge --version v1 --embedder {fake|openai}
  │      stage → embed → validate → activate
  ▼
[DB 색인] PostgreSQL 16 + pgvector: document / document_version / chunk(vector 1536, HNSW cosine) / ingestion_run
  │ ③ 검색  backend/app/rag/retrieval.py search()
  ▼
[RAG 답변] backend/app/rag/pipeline.py (판정 순서 → 검색 → 답변 생성 → 근거 연결, 개발명세서 4절)
```

| 단계 | 처리 | 결과·보장 |
|---|---|---|
| ① 정제 | 59번 Training QA → qa_case(1건=1청크, instruction 제외, 정확 중복 제거, 전화번호·이메일 마스킹, lifeCycle→puppy/adult/senior). Training 원천 말뭉치 → reference(본문의 글자 `\n`만 줄바꿈 변환, 문단 묶음 약 500토큰·1문단 겹침, 문자 위치 보존). Validation QA → 평가 세트(Training과 같은 질문 제외, 진료과 층화 dev 25%/final 75%, seed 고정) | 원본 미수정. 평가 세트는 색인에 들어가지 않음. 토큰 수(cl100k_base)로 임베딩 비용 사전 산정 |
| ② stage | 문서를 (dataset_code, source_record_id)로 식별. 내용 해시와 임베딩 모델이 모두 같으면 건너뜀. 바뀌었거나 새 모델이면 새 document_version(staging)과 청크 생성 | 같은 데이터를 다시 적재해도 중복·추가 비용 없음. 운영자가 비활성·삭제한 문서는 다시 살리지 않음 |
| ② embed | staging 청크만 배치로 임베딩(요청당 토큰 상한), 배치마다 커밋 | 중단 후 재실행하면 남은 청크만 처리(이미 낸 비용 재발생 없음). 유료 실행 전 토큰·예상 비용 표시, `--max-usd` 초과 시 API 호출 전 중단 |
| ② validate | 누락 임베딩·모델 불일치·빈 버전 0건, 표본 20개 자기 검색 1위 확인 | 실패하면 staging을 failed로 두고 활성 색인 유지 |
| ② activate | 한 트랜잭션에서 이전 active 버전 → inactive, 새 버전 → active, document.active_version_id 교체 | 전환 순간에만 검색 결과가 바뀜. 부분 반영 없음 |
| ③ 검색 | active 문서·active 버전·같은 임베딩 모델의 청크만, 생애주기 필터(산출값 OR common OR 미지정)를 같은 쿼리에서 적용. 결과마다 색인 버전(`aihub59/v1+모델명`) 반환 | 서로 다른 모델 벡터를 섞지 않음. answer_run.index_version에 기록할 값 제공 |
| 비활성·삭제 | `--deactivate <id>`: 즉시 검색 제외, 데이터 보존. 삭제: 청크까지 제거, 인용은 제목 스냅샷만 남아 '현재 제공할 수 없는 자료' 표시 | 상담 데이터와 무관 |

실측(가짜 벡터로 전체 적재 검증, 비용 없음): 문서 19,417건(qa_case 19,205 · reference 212), 청크 27,577개, 약 1,679만 토큰, 적재 약 5분, chunk 테이블 약 505MB. 같은 양을 `text-embedding-3-small`로 임베딩하면 약 $0.34로 추정된다(실행 전 단가 재확인).

- 가짜 벡터(`fake-hash-embedding`)는 의미가 없는 시험용이다. 저장·버전·필터·전환을 검증하는 데만 쓰고 검색 품질 평가에 쓰지 않는다. OpenAI 임베딩으로 적재하면 모델이 달라 자동으로 새 버전이 만들어지고, 활성화 시점에 가짜 색인은 검색에서 빠진다.
