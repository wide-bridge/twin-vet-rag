# TwinVet Care 화면설계서

버전: 0.4 · 작성일: 2026-11-09 · 상태: 구조·동작 초안

프론트엔드는 React + TypeScript + Vite로 구현한다. 개발 시 Vite 서버를 사용하고 배포 시 FastAPI가 빌드한 정적 파일을 같은 주소로 제공한다.

시각 디자인은 이 구조를 바탕으로 개발한다. PoC는 **모바일·태블릿·PC 브라우저에서 모두 쓰는 반응형 웹**이다(앱 아님). 화면 수(S01~S03)는 기기와 관계없이 같고, 기기별 배치·동작은 9절을 따른다. 색상·폰트·브랜드 표현은 8절을 따른다.

## 1. PoC 화면 목록

| 화면 | 목적 | 관련 기능 |
|---|---|---|
| S01 시작 | 서비스 범위·데이터 처리 안내와 상담 진입 | P01 |
| S02 상담 | 질문·답변·후속 질문·피드백 | P02/P04/P05/P07 |
| S03 근거 상세 | 문서명·출처 확인. 발췌는 이용 조건 확인 후에만 표시. 패널/모달 | P03 |

PoC에는 회원가입·프로필·수의사·운영자 대시보드를 기본 생성하지 않는다.

## 2. S01 시작

```text
TwinVet Care
반려견 상담 자료를 바탕으로 질문에 답합니다.

지원 대상·상담 주제
AI 정보 제공 범위와 전문가 상담 안내
질문 저장·이용 목적·보관 기간 안내

┌ 응급 안내 (고정) ──────────────────────────────┐
│ 응급 상황이면 AI 답변을 기다리지 마세요.          │
│ 호흡 곤란, 의식 저하, 경련, 심한 출혈, 중독 의심  │
│ 등은 바로 동물병원(야간 24시 병원)에 연락하세요.  │
└──────────────────────────────────────────────────┘

[상담 시작]
```

- 응급 안내는 AI가 생성하지 않는 **고정 문구**다. S01과 S02(입력창 위, 항상 보임)에 표시하고 답변 처리 상태와 무관하게 유지한다. 증상 예시 목록은 PoC 기본안이며 수의사 검토 후 확정한다. 응급 여부를 AI가 판정해 문구를 켜고 끄지 않는다.

- 서비스 범위와 보관 기간은 확정된 설정에 맞춰 표시한다.
- 상담 시작: 세션 확보 후 S02 이동. 첫 질문 전송 때 반려견 정보와 함께 상담을 생성한다. 실패하면 현재 화면에서 재시도 제공.
- 수의사 검토 기능이 없는 PoC에서 ‘수의사 검토 완료’ 또는 실시간 연결을 표시하지 않는다.

## 3. S02 상담

```text
TwinVet Care                 [새 상담] [대화 삭제]
┌ 우리 아이 정보 (첫 질문 전 입력) ─────────────┐
│ 이름 (선택) [두부                              ] │
│ 품종* [말티즈        ▾]  나이* (생일을 알아요|정확히 몰라요) │
│                          [2016년▾][8월▾][일 모름▾] 현재 10세 3개월 │
│ ▸ 건강상태 (선택)                               │
│   체중 [3.2]kg  중성화 (예/아니오/모름)        │
│   기존 질환·복용 약 [               ] 0/300    │
└─────────────────────────────────────────────────┘
첫 질문 후: "두부(말티즈) | 10세 3개월 | 3.2kg" 요약 칩
------------------------------------------------
보호자 질문

AI 답변
[근거 1] [근거 2]
[도움 됐어요] [아쉬워요] [의견 남기기]

후속 질문·답변 …
------------------------------------------------
⚠ 응급 상황이면 답변을 기다리지 말고 바로 동물병원에 연락하세요. (고정)
질문 입력                                  [보내기]
AI 정보 제공 범위 안내
```

| 요소 | 동작 |
|---|---|
| 품종* | 자유 입력 + 자동완성(편의용 목록). '모름'·'믹스견' 선택지 제공. 1~40자 |
| 나이* | 기본 '생일을 알아요': 년(최근 31년)·월('월 모름')·일('일 모름') 선택, 월을 고르기 전에는 일 비활성, 아는 데까지 입력. '정확히 몰라요': 추정 년(0~30)·개월(0~11). 아래에 계산된 나이('현재 10세 3개월', 추정은 '현재 약 3세') 표시. 미래 날짜·없는 날짜·30년 11개월 초과는 텍스트 오류. 좁은 화면(<420px)은 년을 한 줄, 월·일을 다음 줄에 배치 |
| 건강상태(선택) | 기본 접힘. 체중, 중성화 여부, 기존 질환·복용 약(300자). 비워도 전송 가능 |
| 정보 요약 칩 | 첫 전송 후 입력 폼을 읽기 전용 요약('이름(품종) \| 나이 \| 체중')으로 바꿈. 변경하려면 [새 상담] |
| 질문 입력 | 빈 입력 전송 불가. 길이 상한 표시. 줄바꿈과 전송 동작 명확히 구분 |
| 보내기 | 질문 API 호출 후 처리 상태 조회. 중복 클릭 방지 |
| 답변 | AI 생성임을 표시. 오류와 근거 부족을 일반 답변과 구분 |
| 근거 버튼 | S03 열기. 답변에 실제 연결된 출처만 표시 |
| 피드백 | 한 답변에 한 평가, 변경 가능. 의견은 선택 입력 |
| 새 상담 | 빈 대화와 반려견 정보 입력 폼 표시(직전 상담 값을 브라우저에서 미리 채울 수 있음, 서버 프로필 저장 아님). 첫 질문 전송 시 새 consultation 생성. 현재 대화의 자동 삭제를 의미하지 않음 |
| 대화 삭제 | 삭제 범위 확인 후 삭제. 성공하면 새 상담 진입 상태로 이동 |

반려견 고정이며 동물 종류 선택·생애주기 선택 컴포넌트는 만들지 않는다. 품종·나이가 비어 있으면 [보내기]를 비활성화하고 해당 항목에 텍스트 오류를 표시한다. 건강상태 미입력은 오류가 아니다. React 상태·폼 값·API 응답은 TypeScript 타입으로 정의하고 실행 시 입력 검증도 적용한다.

새로고침 시 현재 상담 ID와 서버의 실행 상태로 복구한다. 이력 목록·기기 간 동기화는 기본 범위에 없다.

## 4. S03 근거 상세

- 기본 표시: 문서명·출처, 허용된 원문 링크. 이용 조건 확인 전 인용 구절은 표시하지 않는다.
- 짧은 발췌도 자동 허용으로 간주하지 않는다. 서버가 문서별 허용 여부와 노출 설정을 확인한 경우에만 허용 범위의 발췌를 표시한다.
- 비허용 발췌를 HTML·API 응답에 담아 놓고 숨기지 않는다. 근거 위치는 내부 추적에 보존한다.
- 외부 링크는 허용된 http/https 주소만 사용한다. 내부 저장소 경로는 노출하지 않는다.
- 출처 삭제·권한 제한 시 ‘현재 제공할 수 없는 자료’로 표시하고 구절을 숨긴다.
- 닫으면 S02의 같은 답변 위치로 돌아간다.

## 5. 공통 화면 상태

| 상태 | 표시·행동 |
|---|---|
| 첫 진입 | 지원 주제의 예시 질문과 빈 대화 |
| 처리 중 | ‘답변을 준비하고 있습니다’, 같은 상담 전송 비활성화 |
| 추가 정보 필요 | 확인 질문과 활성화된 입력창 |
| 근거 부족 | ‘확인할 자료가 부족합니다’, 질문 구체화 안내 |
| 범위 밖 | 지원 범위 안내 |
| 실패 | 간단한 오류 설명과 재시도 버튼. 기존 질문 유지 |
| 세션 만료 | 재시작 안내. 이전 내용에 접근할 수 있다고 약속하지 않음 |
| 삭제 실패 | 기존 대화 유지, 실패 안내와 재시도 |

기기별 배치는 9절을 따른다. 키보드 이동·포커스·텍스트 오류 설명을 제공하며 색만으로 상태를 구분하지 않는다.

MVP 인증·권한 화면과 검토 알림 방식은 운영 정책 확정 후 설계한다.

## 7. 나이 표시

나이만 년·개월로 표시한다(생년월을 앎: '10세 3개월', 출생 연도만: '약 10세', 추정: '약 10세 3개월(추정)'). 생년월일은 나이와 중복되므로 표시하지 않고 저장만 한다(2026-11-11 사용자 결정). 마지막 입력 정보로 새 상담을 채울 때 생년월일은 그대로, 추정 나이는 지난 기간만큼 더한다. 생애주기 명칭과 나이 구간은 표시하지 않는다. 품종·체중 등 기존 정보 표시는 유지한다. 생애주기 산출값은 내부 검색에만 사용한다.

## 8. Google Stitch 전달 지시문 (PoC S01~S03)

기준일: 2026-11-09. 상태: 초안(Claude Code 설계 제안, PM·사용자 검토 필요) — Stitch 시안 생성용 지시문.
이 절은 시각 시안 요청서다. Stitch 산출물은 시안이며, 실제 화면은 Claude Code가 React 컴포넌트로 다시 구현한다. 문구 중 [ ]로 표시한 값은 미확정이다.

### 8-1. 시각 규칙 (설계 제안)

| 항목 | 요구사항 |
|---|---|
| 인상 | 차분하고 믿을 수 있는, 따뜻한 상담 창구. 병원 차트·의료 경고판 같은 차가운 인상과 귀여운 캐릭터 앱 같은 가벼운 인상을 모두 피한다 |
| 색 | 주 색상: 차분한 청록·녹색 계열 1개. 배경은 밝은 중성색. 빨강·주황은 응급 안내에만 쓴다. 상태는 색만으로 구분하지 않고 아이콘+문구를 함께 쓴다(WCAG AA 대비) |
| 글꼴 | 한국어 가독성 우선 산세리프(Pretendard 또는 Noto Sans KR). 본문 16px 이상 |
| 레이아웃 | 반응형 웹, 모바일 우선. 기기별 배치는 9절. 터치 영역 44px 이상 |
| 이미지 | 사진·일러스트는 S01 상단에 작게 1개까지. 흰 가운 입은 수의사·의사 이미지는 쓰지 않는다(수의사 상담으로 오해) |
| 말투 | 존댓말, 짧고 쉬운 문장. "진단·처방·치료해 드립니다" 같은 표현 금지 |

### 8-2. 화면에 넣지 않을 것

로그인·회원가입, 대화 목록 사이드바·이전 상담 이력, 동물 종류 선택(고양이 등), 생애주기 명칭이나 나이 구간("노령견", "7세 이상"), 수의사 검토·인증 배지, 수의사 실시간 연결, 이미지·음성 입력, 병원 예약·결제, 별점, 근거 원문 구절 표시, AI 캐릭터 이름·아바타.

### 8-3. 확정 문구 초안

| 위치 | 문구 |
|---|---|
| S01 제목 | 반려견 건강 궁금증, 상담 자료로 함께 찾아봐요 |
| S01 지원 범위 | 반려견(강아지)의 일반 건강 질문을 도와드려요. 내과·외과·피부·눈·치아 관련 상담 자료를 바탕으로 답합니다. |
| S01 AI 안내 | AI가 상담 사례와 수의학 자료를 찾아 정리한 정보예요. 진단이나 처방이 아니며, 정확한 판단은 동물병원에서 받으세요. |
| S01 저장 안내 | 질문과 입력한 반려견 정보는 답변을 위해 저장돼요. 이 브라우저에서 [7일]간 볼 수 있고 이후 자동 삭제되며, 언제든 직접 삭제할 수 있어요. |
| 응급 안내(전체) | 응급 상황이면 AI 답변을 기다리지 마세요. 호흡 곤란, 의식 저하, 경련, 심한 출혈, 중독 의심 등은 바로 동물병원(야간에는 24시 동물병원)에 연락하세요. |
| 응급 안내(S02 한 줄) | ⚠ 응급하면 바로 동물병원에 연락하세요 (360px 폭에서 한 줄에 들어가는 길이 유지) |
| 나이 도움말 | 아는 데까지만 입력해 주세요. 월·일은 몰라도 돼요 / 대략적인 나이를 입력해 주세요 |
| 예시 질문(첫 진입) | 하루에 두 번 토했는데 병원에 가야 할까요? / 귀를 자주 긁고 냄새가 나요 / 슬개골 탈구는 집에서 어떻게 관리하나요? / 눈곱이 갑자기 많아졌어요 |
| 처리 중 | 답변을 준비하고 있어요 |
| 추가 확인 | 정확히 안내하려면 조금 더 알려주세요 (+ AI의 확인 질문) |
| 근거 부족 | 확인할 수 있는 자료가 부족해요. 증상·기간·상황을 더 구체적으로 적어 주시거나 동물병원에 문의해 주세요. |
| 범위 밖 | 반려견 건강 질문만 도와드릴 수 있어요. |
| 실패 | 답변을 가져오지 못했어요. [다시 시도] |
| 세션 만료 | 상담 시간이 만료되어 이전 대화는 볼 수 없어요. [새 상담 시작] |
| 대화 삭제 확인 | 이 대화를 삭제할까요? 질문·답변·입력한 반려견 정보가 모두 삭제되며 되돌릴 수 없어요. [취소] [삭제] |

## 9. 반응형 배치·동작 기준

화면 수(S01~S03)는 그대로 두고 기기 폭에 따라 배치만 바꾼다. 별도 모바일 앱·모바일 전용 화면은 만들지 않는다.

### 9-1. 기준 폭

| 구분 | 폭(CSS px) | 기본 배치 |
|---|---|---|
| 모바일 | 767 이하 | 화면 너비에 맞춘 한 열. 좌우 여백 16px |
| 태블릿 | 768~1023 | 한 열, 콘텐츠 최대 너비 720px 가운데 정렬. 근거 상세는 모바일과 같은 전체 화면 모달 |
| PC | 1024 이상 | 콘텐츠 최대 너비 720px 가운데 정렬. 근거 상세는 오른쪽 패널(약 360px) |

최소 지원 폭은 320px이다. 모든 폭에서 가로 스크롤이 생기지 않아야 한다. 고정 높이를 쓰지 않아 브라우저 확대 200%에서도 내용이 잘리지 않게 한다.

### 9-2. 화면별 배치

| 화면·요소 | 모바일 | PC |
|---|---|---|
| S01 시작 | 세로 배치: 제목 → 지원 범위 → AI 안내 → 저장 안내 → 응급 안내 박스 → [상담 시작]. 버튼은 전체 너비 | 가운데 정렬, 최대 너비 720px. [상담 시작]은 내용 아래 가운데, 고정 너비 |
| 반려견 정보 카드 | 항목을 세로로: 이름(선택) → 품종 → 나이(년·개월 한 줄) → 건강상태(접힘) | 품종·나이를 같은 줄에 배치, 건강상태는 아래 줄에서 펼침. 펼친 건강상태는 체중·중성화를 같은 줄, 기존 질환은 다음 줄 |
| 요약 칩(첫 질문 후) | 한 줄, 길면 말줄임 없이 줄바꿈 | 한 줄 |
| S02 대화 영역 | 화면 너비에 맞춤. 답변 텍스트·근거 칩·피드백 버튼이 폭을 넘지 않게 줄바꿈 | 최대 너비 720px로 제한해 한 줄 길이가 과도하게 길어지지 않게 함 |
| 헤더 | 제목 + 메뉴 버튼(새 상담, 대화 삭제) | 제목 + 버튼 2개 |
| 질문 입력 | 하단 고정. 입력창은 내용에 따라 최대 4줄까지 늘어나고 이후 내부 스크롤 | 하단 고정, 대화 영역과 같은 최대 너비 |
| 응급 안내(S02) | 입력창 바로 위 짧은 한 줄 고정. 대화 영역을 한 줄 높이 이상 차지하지 않음. 누르면 전체 문구를 대화상자로 표시 | 같음 |
| S03 근거 상세 | 전체 화면 모달. 상단에 닫기 버튼, 브라우저 뒤로 가기로도 닫힘. 닫으면 보던 답변 위치로 복귀 | 오른쪽 패널. 대화 영역은 그대로 보이며 패널만 닫힘. 패널이 열리면 대화+패널 합계 폭에 맞게 배치 |
| 대화상자(삭제 확인 등) | 화면 아래쪽 또는 가운데, 버튼은 전체 너비로 세로 배치 | 가운데 작은 대화상자, 버튼 가로 배치 |

### 9-3. 입력·키보드 동작

- 모바일 키보드가 열려도 입력창·보내기 버튼·응급 한 줄 안내가 보여야 한다. 화면 높이는 키보드를 반영하는 동적 높이(dvh, visualViewport)로 계산하고, 하단 안전 영역(노치·홈 막대)을 비운다.
- 키보드가 열리면 대화 영역만 줄어들고 최신 메시지가 보이도록 스크롤한다. 반려견 정보 카드가 입력 중 화면을 가리지 않게 한다.
- 전송 키: PC는 Enter 전송, Shift+Enter 줄바꿈. 모바일은 Enter 줄바꿈, [보내기] 버튼으로 전송. 입력창 아래 안내 문구로 알린다.
- 입력 글꼴은 16px 이상으로 해 iOS 브라우저의 자동 확대를 막는다.
- 가로 모드(높이가 낮은 화면)에서는 요약 칩을 숨기지 않되 한 줄로 줄이고, 대화 영역이 최소 몇 줄은 보이도록 헤더 높이를 줄인다.

### 9-4. 긴 내용

- 긴 답변: 높이 제한 없이 표시하고 대화 영역 스크롤로 본다. 문단·목록 간격을 유지한다.
- 긴 단어·URL·자료명: 줄바꿈 허용(overflow-wrap). 근거 칩의 자료명은 2줄까지 표시 후 말줄임, 전체 이름은 근거 상세에서 표시.
- 긴 품종명·기존 질환: 입력·요약 모두 줄바꿈 처리하고 레이아웃을 밀어내지 않는다.
