# TwinVet Care 화면설계서

버전: 0.4 · 작성일: 2026-11-09 · 상태: 구조·동작 초안

프론트엔드는 React + TypeScript + Vite로 구현한다. 개발 시 Vite 서버를 사용하고 배포 시 FastAPI가 빌드한 정적 파일을 같은 주소로 제공한다.

시각 디자인은 이 구조를 바탕으로 개발한다. PoC는 모바일·데스크톱 웹을 지원하는 안으로 제안한다. 색상·폰트·브랜드 표현은 디자인 단계에서 정한다.

## 1. PoC 화면 목록

| 화면 | 목적 | 관련 기능 |
|---|---|---|
| S01 시작 | 서비스 범위·데이터 처리 안내와 상담 진입 | P01 |
| S02 상담 | 질문·답변·후속 질문·피드백 | P02/P04/P05/P07 |
| S03 근거 상세 | 문서명·출처 확인. 발췌는 이용 조건 확인 후에만 표시. 패널/모달 | P03 |

PoC에는 회원가입·프로필·수의사·운영자 대시보드를 기본 생성하지 않는다.

## 2. S01 시작

```text
TwinVet Care
반려견 상담 자료를 바탕으로 질문에 답합니다.

지원 대상·상담 주제
AI 정보 제공 범위와 전문가 상담 안내
질문 저장·이용 목적·보관 기간 안내

┌ 응급 안내 (고정) ──────────────────────────────┐
│ 응급 상황이면 AI 답변을 기다리지 마세요.          │
│ 호흡 곤란, 의식 저하, 경련, 심한 출혈, 중독 의심  │
│ 등은 바로 동물병원(야간 24시 병원)에 연락하세요.  │
└──────────────────────────────────────────────────┘

[상담 시작]
```

- 응급 안내는 AI가 생성하지 않는 **고정 문구**다. S01과 S02(입력창 위, 항상 보임)에 표시하고 답변 처리 상태와 무관하게 유지한다. 증상 예시 목록은 PoC 기본안이며 수의사 검토 후 확정한다. 응급 여부를 AI가 판정해 문구를 켜고 끄지 않는다.

- 서비스 범위와 보관 기간은 확정된 설정에 맞춰 표시한다.
- 상담 시작: 세션 확보 후 S02 이동. 첫 질문 전송 때 반려견 정보와 함께 상담을 생성한다. 실패하면 현재 화면에서 재시도 제공.
- 수의사 검토 기능이 없는 PoC에서 ‘수의사 검토 완료’ 또는 실시간 연결을 표시하지 않는다.

## 3. S02 상담

```text
TwinVet Care                 [새 상담] [대화 삭제]
┌ 우리 아이 정보 (첫 질문 전 입력) ─────────────┐
│ 품종* [말티즈        ▾]  나이* [10]년 [3]개월 │
│ ▸ 건강상태 (선택)                               │
│   체중 [3.2]kg  중성화 (예/아니오/모름)        │
│   기존 질환·복용 약 [               ] 0/300    │
└─────────────────────────────────────────────────┘
첫 질문 후: "말티즈 · 10세 3개월 · 나이 든 반려견 · 3.2kg" 요약 칩
------------------------------------------------
보호자 질문

AI 답변
[근거 1] [근거 2]
[도움 됐어요] [아쉬워요] [의견 남기기]

후속 질문·답변 …
------------------------------------------------
⚠ 응급 상황이면 답변을 기다리지 말고 바로 동물병원에 연락하세요. (고정)
질문 입력                                  [보내기]
AI 정보 제공 범위 안내
```

| 요소 | 동작 |
|---|---|
| 품종* | 자유 입력 + 자동완성(편의용 목록). '모름'·'믹스견' 선택지 제공. 1~40자 |
| 나이* | 년(0~30)·개월(0~11). '정확하지 않아도 괜찮아요' 안내. 둘 다 0이면 '1개월 미만'으로 표시 |
| 건강상태(선택) | 기본 접힘. 체중, 중성화 여부, 기존 질환·복용 약(300자). 비워도 전송 가능 |
| 정보 요약 칩 | 첫 전송 후 입력 폼을 읽기 전용 요약(품종·나이·산출 생애주기·체중)으로 바꿈. 변경하려면 [새 상담] |
| 질문 입력 | 빈 입력 전송 불가. 길이 상한 표시. 줄바꿈과 전송 동작 명확히 구분 |
| 보내기 | 질문 API 호출 후 처리 상태 조회. 중복 클릭 방지 |
| 답변 | AI 생성임을 표시. 오류와 근거 부족을 일반 답변과 구분 |
| 근거 버튼 | S03 열기. 답변에 실제 연결된 출처만 표시 |
| 피드백 | 한 답변에 한 평가, 변경 가능. 의견은 선택 입력 |
| 새 상담 | 빈 대화와 반려견 정보 입력 폼 표시(직전 상담 값을 브라우저에서 미리 채울 수 있음, 서버 프로필 저장 아님). 첫 질문 전송 시 새 consultation 생성. 현재 대화의 자동 삭제를 의미하지 않음 |
| 대화 삭제 | 삭제 범위 확인 후 삭제. 성공하면 새 상담 진입 상태로 이동 |

반려견 고정이며 동물 종류 선택·생애주기 선택 컴포넌트는 만들지 않는다. 품종·나이가 비어 있으면 [보내기]를 비활성화하고 해당 항목에 텍스트 오류를 표시한다. 건강상태 미입력은 오류가 아니다. React 상태·폼 값·API 응답은 TypeScript 타입으로 정의하고 실행 시 입력 검증도 적용한다.

새로고침 시 현재 상담 ID와 서버의 실행 상태로 복구한다. 이력 목록·기기 간 동기화는 기본 범위에 없다.

## 4. S03 근거 상세

- 기본 표시: 문서명·출처, 허용된 원문 링크. 이용 조건 확인 전 인용 구절은 표시하지 않는다.
- 짧은 발췌도 자동 허용으로 간주하지 않는다. 서버가 문서별 허용 여부와 노출 설정을 확인한 경우에만 허용 범위의 발췌를 표시한다.
- 비허용 발췌를 HTML·API 응답에 담아 놓고 숨기지 않는다. 근거 위치는 내부 추적에 보존한다.
- 외부 링크는 허용된 http/https 주소만 사용한다. 내부 저장소 경로는 노출하지 않는다.
- 출처 삭제·권한 제한 시 ‘현재 제공할 수 없는 자료’로 표시하고 구절을 숨긴다.
- 닫으면 S02의 같은 답변 위치로 돌아간다.

## 5. 공통 화면 상태

| 상태 | 표시·행동 |
|---|---|
| 첫 진입 | 지원 주제의 예시 질문과 빈 대화 |
| 처리 중 | ‘답변을 준비하고 있습니다’, 같은 상담 전송 비활성화 |
| 추가 정보 필요 | 확인 질문과 활성화된 입력창 |
| 근거 부족 | ‘확인할 자료가 부족합니다’, 질문 구체화 안내 |
| 범위 밖 | 지원 범위 안내 |
| 실패 | 간단한 오류 설명과 재시도 버튼. 기존 질문 유지 |
| 세션 만료 | 재시작 안내. 이전 내용에 접근할 수 있다고 약속하지 않음 |
| 삭제 실패 | 기존 대화 유지, 실패 안내와 재시도 |

모바일에서는 한 열로 배치하고 입력창이 키보드에 가려지지 않게 한다. 키보드 이동·포커스·텍스트 오류 설명을 제공하며 색만으로 상태를 구분하지 않는다.

## 6. MVP 추가 화면

| 화면 | 핵심 구성 |
|---|---|
| S04 검토 요청·상태 | 공유할 상담 범위, 동의, 요청·취소, 대기·추가 질문·완료 표시 |
| S05 수의사 검토 목록 | 배정된 요청, 상태, 요청 시각, 검토 진입 |
| S06 수의사 검토 상세 | 상담 원문, AI 답변, 문서·구조화 지식 근거, 수정·승인·추가 질문 |
| S07 검토 결과 | 수의사 검토 여부, 검토자·시각, 최종 안내, AI 원답변과 구분 |

M01 지식그래프/온톨로지 결과는 우선 S03에서 이해할 수 있는 관계·조건·출처로 보여준다. 그래프 시각화 화면은 실제 사용 필요가 있을 때 추가한다.

MVP 인증·권한 화면과 검토 알림 방식은 운영 정책 확정 후 설계한다.

## 7. 생애주기 표시 용어

| 데이터 용어 | 사용자 표시 |
|---|---|
| 자견 (puppy) | 어린 강아지 |
| 성견 (adult) | 성장한 반려견 |
| 노령견 (senior) | 나이 든 반려견 |

상담 상단 요약과 생애주기를 보여주는 모든 사용자 화면에 위 표현을 적용한다. 원천 데이터 용어·DB/API 코드·검색 기준은 유지한다.
